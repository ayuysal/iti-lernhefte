Kapitel 1

Peer-to-Peer- und Client-Server-Netze

Zuletzt gelesen

Aus administrativer Sicht gibt es letztlich nur zwei Netzarchitekturen: Client-Server und Peer-to-Peer (P2P). Beide folgen auf den unteren OSI-Schichten exakt dem gleichen TCP/IP-Prinzip – der Unterschied liegt allein in der Rollenverteilung auf der Anwendungsschicht.

Server ist eine Rolle, kein Rechner

Ein Server ist ein Programm (Prozess), das einem anderen Programm, dem Client (Kunde, Dienstnutzer), Zugang zu einem Dienst verschafft. Ein Rechner kann Server und Client zugleich sein. Im P2P-Netz (Peer = Gleichgestellter) ist genau das der Normalfall: Jeder Peer ist gleichzeitig Client und Server, das Rollenspiel wechselt laufend.

Prüfungsfalle: OSI-Schichten

Der Unterschied zwischen Client-Server und P2P liegt ausschliesslich auf der Anwendungsschicht (Rollenverteilung). Auf den darunterliegenden Schichten – Transport (TCP/UDP) und Vermittlung (IP) – läuft in beiden Architekturen exakt das gleiche TCP/IP-Protokoll. Das ist die zentrale Gemeinsamkeit, nach der Prüfungsfragen gern fragen.

Historisch ist P2P sogar die Ursprungsform: Die ersten vier ARPANET-Hosts waren gleichberechtigte Rechner. Heute dominieren Client-Server-Netze, vor allem dank Cloud-Computing; P2P lebt in Nischen weiter (File-Sharing) und in neuer Form in der Blockchain, siehe Kapitel 2. Eine Mischform sind verteilte Systeme: eine logische Erweiterung des Client-Server-Modells, bei der Aufgaben auf mehrere Server verteilt werden.

Server-Prozesse: Sockets und Ports

Zwischen zwei Kommunikationsprozessen besteht eine feste Zuordnung aus Protokoll, lokaler/entfernter Rechneradresse und lokaler/entfernter Portnummer. Die Kombination aus IP-Adresse und Portnummer heisst Socket.

Iterativer vs. paralleler Server

Ein Server muss stets mehrere Clients bedienen (1:n-Beziehung). Dafür gibt es zwei Arbeitsweisen:

Zwei Serverklassen

Iterativer Server: bearbeitet jede Anfrage selbst, sendet die Antwort und geht danach zurück in den Wartezustand – einfach, aber es kann immer nur ein Client gleichzeitig bedient werden. Paralleler Server: startet für jede eingehende Anfrage einen neuen Prozess/Thread (auch Child-Server-Prozess, Forking Server oder Concurrent Server genannt), der die Antwort übernimmt; der Hauptprozess ist sofort wieder frei für die nächste Anfrage – quasi nach dem Multitasking-Prinzip.

Prüfungsfalle

„Paralleler Server ist immer besser“ stimmt nicht: Bei hoher Netzbelastung leidet trotzdem das Gesamtverhalten, und nicht jede Aufgabe profitiert von Parallelität – ein Netzwerkdrucker hat trotzdem meist nur einen Papierschacht bzw. Laserkopf. Der parallele Server ist zudem kein Multiprozessorsystem; es handelt sich um Nebenläufigkeit (Concurrency), nicht zwingend um echte Parallelität.

Kapitel 2

Anwendungen im Internet

Zuletzt gelesen

Internet ≠ WWW. Das ARPANET als Vorläufer des Internets ging 1969 in Betrieb, das World Wide Web erfand Tim Berners-Lee erst 20 Jahre später (März 1989, CERN) als Wissensmanagement-Projekt. Das WWW hat das Internet zur Erfolgsgeschichte gemacht, ist aber nur einer seiner Dienste.

World Wide Web, HTTP und HTML

WWW als Client-Server-Dienst

Das WWW folgt dem Client-Server-Prinzip und ist verbindungsorientiert. Der Browser (Client) fordert Inhalte per HTTP-Request an, der WWW-Server liefert per HTTP-Response. HTTP (Hypertext Transfer Protocol) baut auf TCP auf und ist zustandslos – ein einfaches Frage-Antwort-Schema ohne Gedächtnis zwischen den Anfragen. HTTPS überträgt zusätzlich verschlüsselt; seit 2015 gibt es mit HTTP/2 (RFC 7540) eine performantere Weiterentwicklung.

Inhalte liegen als Hypermedia-Dokumente vor – vernetzt über Hyperlinks. Die Darstellungssprache ist HTML (Hypertext Markup Language): eine Markup-, keine Programmiersprache, mit Fokus auf Struktur und Formatierung. XML (eXtensible Markup Language, W3C 1998) ist eine Meta-Markup-Sprache, aus der anwendungsspezifische Sprachen wie WML, RSS oder SVG abgeleitet sind. Ergänzend trennt CSS Inhalt und Darstellung, JavaScript ermöglicht clientseitig dynamische Seiten, und PHP erzeugt serverseitig dynamische Inhalte.

Aufbau einer URL

Über eine URL (Uniform Resource Locator) ruft der Browser eine Ressource ab; ein DNS-Dienst (Domain Name System) löst den Namen rekursiv – von rechts nach links gelesen – in eine IP-Adresse auf.

Eine einzelne Webseite braucht dafür oft mehrere solcher Anfragen.

E-Mail: Aufbau, SMTP, POP3, IMAP

Aufbau einer E-Mail

Eine E-Mail besteht aus drei Teilen: Envelope (gehört zum Transportprotokoll, für den Empfänger nicht sichtbar), Header (Metadaten wie Date, From, To, Cc, Bcc, Reply-To, Subject, Message-ID) und Body (eigentlicher Inhalt). Die Adresssyntax benutzer@domain.tld folgt RFC 5321/5322: „@“ ist das einzige Trennzeichen, der Punkt im Domainnamen trennt Domain und TLD – gleiche Logik wie bei einer URL. Der MIME-Standard (1993) erweitert das ursprünglich reine 7-Bit-ASCII-Format um Anhänge (Bild, Audio, Video …) und nationale Sonderzeichen.

ProtokollPortAufgabe
SMTP25 (465 mit TLS/SSL)Versenden zwischen MTAs (Message Transfer Agents); reines Sendeprotokoll nach Client-Server-Prinzip, auch zwischen zwei Servern
POP3110Abruf: lädt E-Mails herunter und löscht sie danach vom Server – wie ein klassischer Briefkasten
IMAP143Abruf: lädt zunächst nur die Header, der Mailserver bleibt zentrales Repository – synchron über mehrere Endgeräte
Prüfungsfalle POP3 vs. IMAP

POP3 entleert das Postfach beim Abruf (effizient, aber nicht geräteübergreifend synchron). IMAP hält die gesamte Ordnerstruktur zentral auf dem Server – Posteingang, Gesendet, Entwürfe, Gelöscht – und synchronisiert sie auf allen Geräten. Wer mehrere Endgeräte nutzt, braucht IMAP.

Blockchain

Definition

Die Blockchain ist ein auf beliebig vielen Rechnern verteiltes, öffentliches Transaktions-Logbuch (Distributed Ledger) für ein digitales Gut. Sie entstand 2008/2009 (Satoshi Nakamoto, Whitepaper „Bitcoin: A Peer-to-Peer Electronic Cash System“) aus dem Vertrauensverlust in Banken nach der Finanzkrise – Ziel war ein System ohne zentrale Instanz, ganz im Sinne des P2P-Prinzips aus Kapitel 1.

Jede Transaktion wird digital signiert, im P2P-Netz verteilt und von allen Teilnehmern geprüft (Konsensverfahren). Nach Konsens wird sie einem neuen Block hinzugefügt; jeder Block referenziert per Hashwert den vorigen – so entsteht die Chain. Die Transaktionen eines Blocks werden zusätzlich in einem Merkle-Tree (Ralph Merkle, 1979) zusammengefasst. Konkurrierende Miner lösen dafür ein mathematisches Rätsel (Mining); wer zuerst fertig ist, erhält eine Belohnung. Entstehen dabei zeitgleich zwei Zweige (Fork), gilt eine feste Regel:

Die längste Kette ist stets die gültige Kette.

Der kürzere Zweig wird zum Orphan-Block und verwaist. Der allererste Block einer Chain heisst Genesis-Block. Weil jede nachträgliche Änderung alle Folge-Hashes bricht und mindestens die Hälfte aller Teilnehmer manipuliert werden müsste, gilt die Blockchain als praktisch fälschungssicher. Smart Contracts erweitern sie um selbstausführende Verträge nach dem If-Then-Prinzip.

Kernvorteile: kein Intermediär nötig, hohe Manipulationssicherheit, schnelle automatisierte Abwicklung von Standardprozessen. Anwendungsgebiete finden sich praktisch branchenübergreifend, u. a. in Logistik/Warenwirtschaft (lückenlose Herkunftsverfolgung), Finanzwesen (Kryptowährungen, Zahlungsabwicklung), Energieversorgung (P2P-Stromhandel), Medizin/Pharma (fälschungssichere Patientenakten), Identitätsmanagement sowie Cloud Computing und Internet of Things.

Kapitel 3

Management von Computernetzen

Zuletzt gelesen

Netzwerkmanagement kümmert sich um Hard- und Softwareprobleme, Überlastungen und Verbindungsunterbrechungen auf Netzkomponenten und Servern – betrachtet nach Netztyp, Informationsart, Disziplin, Funktionsklasse und Betriebsphase. Damit Aussagen wie „das Internet ist heute langsam“ objektiv vergleichbar werden, standardisiert das OSI Management Framework (ISO/IEC 7498-4) das Vorgehen.

Netzwerk-Monitoring

OSI Management Framework – fünf Funktionsklassen

Performance-Management: Bewertung von Verhalten und Effektivität der Verbindungsaktivitäten. Fault-Management: Erkennung, Bearbeitung und Behebung von Fehlerzuständen, Alarm- und Log-Handling. Configuration-Management: zentrale Identifikation, Überwachung und Kontrolle der Managed Objects zur unterbrechungsfreien Operation. Security-Management: Kontrolle und Verteilung von Informationen zur Sicherstellung der Informationsintegrität. Accounting-Management: leistungsbezogene Verrechnung des Netzwerk-Management-Dienstes.

SNMP – Simple Network Management Protocol

SNMP sitzt im TCP/IP-Modell auf der Anwendungsschicht und nutzt UDP (Port 161, Traps auf Port 162). Aktuelle Version: SNMPv3 (seit Dezember 2002, abwärtskompatibel). Die Kommunikation läuft standardmässig im Klartext – ein bekanntes Sicherheitsrisiko, weshalb SNMP an Netzgrenzen oft blockiert werden sollte.

Manager und Agent

SNMP basiert auf zwei Rollen: Der Manager (Software auf einem NMS, Network Management System) überwacht, steuert und protokolliert – nur er führt Analysen durch. Die Agenten laufen als Managed Objects direkt auf den Netzkomponenten (Router, Switch, Server) und melden ihren Status. Das Frage-Antwort-Schema zwischen beiden ist bewusst simpel gehalten.

BegriffBedeutung

Prüfungsfalle

Der Agent ist nicht in das NMS eingebettet, sondern läuft auf der überwachten Komponente selbst. TRAP-Messages werden vom Agenten ausgelöst, nicht vom Manager – nur GET und SET gehen vom Manager aus. Und: Jede OID ist per Definition eindeutig, es gibt sie immer nur einmal.

Implementierungen in der Praxis

WMI (Windows Management Instrumentation) ist das flexiblere Windows-Bordmittel. Hyperic HQ (Open Source) eignet sich für virtuelle Maschinen und Cloud-Infrastrukturen, mit automatischer Ressourcenerkennung (Auto-Discovery). Nagios gilt als Industriestandard, arbeitet als Baukastensystem (Windows-Hosts benötigen zusätzlich den NSClient++). PRTG (Paessler, kommerziell) sucht Sensoren automatisch, statt sie wie bei Nagios manuell einzutragen.

Kapitel 4 · rechenlastig

Informationssicherheit

Zuletzt gelesen

Verschlüsselung ist kein Bestandteil des OSI-Schichtenmodells – ohne kryptografische Verfahren könnte jedes Datenpaket auf seinem Weg durchs Netz mitgelesen oder verändert werden (Stichwort Man-in-the-Middle). Kryptografie sichert damit Vertraulichkeit, Integrität und Authentizität der Kommunikation.

Kerckhoff-Prinzip

Die Sicherheit eines kryptografischen Verfahrens soll auf der Geheimhaltung des Schlüssels beruhen, nicht auf der Geheimhaltung des Verfahrens selbst. Ein Verfahren lässt sich ohnehin kaum dauerhaft geheim halten; öffentlich bekannte, von Experten geprüfte Verfahren wie AES oder RSA gelten gerade deshalb als sicher.

Kryptografie: symmetrisch vs. asymmetrisch

Verschlüsselung des Klartextes (Plaintext) P mit dem Encryption Key: C = E_K(P). Entschlüsselung des Chiffretextes (Cipher-Text) C mit dem Decryption Key: P = D_K(C) – Decryption ist die Umkehrfunktion der Encryption.

SymmetrischAsymmetrisch
Schlüsselein gemeinsamer Schlüssel für Ver- und Entschlüsselung (EK = DK)Schlüsselpaar: öffentlicher Schlüssel (Public Key) + privater Schlüssel (Private Key)
Risikoder Schlüsselaustausch selbst ist die SchwachstellePublic Key ist beliebig verteilbar – risikofrei
Aufwandgering, schnellrechenintensiv, dafür ab ca. 5 Teilnehmern deutlich weniger Schlüssel nötig
BeispieleDES, IDEA, AESRSA (1977, Rivest/Shamir/Adleman)
RSA-Verfahren – Rechenbeispiel

RSA basiert auf dem Produkt zweier grosser Primzahlen, dessen Faktorisierung praktisch nicht in vertretbarer Zeit lösbar ist. Ablauf anhand kleiner Zahlen:

1. Primzahlen wählen: p = 17, q = 31 2. Produkt: N = p · q = 527 3. Eulersche Phi-Funktion: φ(N) = (p−1)(q−1) = 16 · 30 = 480 4. e teilerfremd zu φ(N) und kleiner als φ(N) wählen: e = 13 → öffentlicher Schlüssel (e, N) = (13, 527) 5. d als Modulo-Inverses zu e bestimmen: e · d mod φ(N) = 1 → 13 · 37 mod 480 = 481 mod 480 = 1 → privater Schlüssel (d, N) = (37, 527) Verschlüsseln (mit öffentlichem Schlüssel): C = Mᵉ mod N Nachricht „X“ = ASCII 88 → C = 88¹³ mod 527 = 522 Entschlüsseln (mit privatem Schlüssel): M = Cᵈ mod N M = 522³⁷ mod 527 = 88 = „X“

In der Praxis verlangt das BSI Schlüssellängen von N ab 2000 bis 3000 Bit, damit die Primfaktorzerlegung selbst mit heutiger Rechenleistung Jahre dauert und so vor Brute-Force-Attacken schützt.

Digitale Signatur

Die digitale Signatur ist eine hybride Anwendung: asymmetrische Verschlüsselung kombiniert mit einer Hashfunktion (Hybride Verschlüsselung insgesamt: asymmetrisch für den Schlüsseltausch, symmetrisch für die eigentliche Nutzdatenverschlüsselung). Eine Hashfunktion ist eine Einweg-Funktion (kein Rückschluss auf die Eingabe möglich) mit fester Ausgabelänge, die zusätzlich kollisionssicher sein muss – keine zwei Eingaben dürfen den gleichen Hashwert liefern.

Prüfungsfalle: Schlüsselrichtung gedreht

Bei der digitalen Signatur wird die Schlüsselnutzung der normalen asymmetrischen Verschlüsselung umgekehrt: Der Sender verschlüsselt den Hashwert seiner Nachricht mit seinem eigenen privaten Schlüssel (Signatur). Der Empfänger prüft mit dem öffentlichen Schlüssel des Senders (Verifikation). Die Nachricht selbst bleibt dabei im Klartext lesbar – nur der Hashwert wird signiert.

Sicherheitsangriffe

Bei passiven Angriffen sammelt der Angreifer nur Informationen (Sniffing), ohne einzugreifen; erst der aktive Angriff manipuliert gezielt, etwa als Man-in-the-Middle.

AngriffMerkmal
Brute-Forcesystematisches Durchprobieren aller Zeichenkombinationen, bis Passwort/Schlüssel gefunden ist
Social Engineering„Chef-Trick statt Enkel-Trick“ – psychologische Manipulation von Mitarbeitenden anhand recherchierter Insider-Informationen; die Schwachstelle „Mensch“ lässt sich nur durch regelmässiges Training absichern
Man-in-the-MiddleAngreifer nistet sich zwischen zwei Kommunikationspartner, hört mit und manipuliert

Malware unterscheidet sich vor allem nach Verbreitungsweg: Viren brauchen einen Wirt und werden erst beim Ausführen aktiv, Würmer verbreiten sich selbständig (z. B. via Adressbuch), Trojaner verstecken sich in scheinbar nützlicher Software und spähen Daten aus, Backdoors öffnen versteckte, oft erst Jahre später aktive Hintertüren, Spyware protokolliert Nutzeraktivitäten (z. Hinweis zur Nutzung

Die Lösungen unten sind meine eigenen Rechen- und Argumentationswege zum Abgleich, nicht der offizielle Lösungsschlüssel. Formuliere für die Abgabe in eigenen Worten und rechne die Zahlen selbst nach – kleine Rundungsabweichungen sind normal.

1Client-Server vs. Peer-to-Peer20 Pkt.

Erklären Sie den Unterschied zwischen einem Client-Server und einem Peer-to-Peer Netzwerk. Nennen Sie ebenso Beispiele oder Einsatzgebiete und wesentliche Anforderungen und Eigenschaften. Auf welchen OSI-Schichten gibt es eine Unterscheidung bzw. Gemeinsamkeiten?

Lösungsweg

Client-Server: Ein dedizierter Server stellt Dienste bzw. Ressourcen bereit, die Clients sind reine Leistungsnehmer. Vorteile: zentrale Verwaltung und Datensicherung, Betriebssicherheit leichter zu realisieren. Nachteil: Der Server ist ein Single Point of Failure und kann bei Massenanfragen zum Bottleneck werden.

Peer-to-Peer: Alle Knoten sind gleichberechtigt, jeder Knoten ist gleichzeitig Client und Server. Das Netz ist dezentral und selbstorganisierend, das bringt gute Skalierbarkeit und Fehlertoleranz – der Ausfall einzelner Peers ist kein Gesamtproblem. Dem stehen Sicherheits- und Administrationsprobleme gegenüber, da es keine zentrale Kontrollinstanz gibt.

Beispiele Client-Server: WWW (Browser ↔ Webserver), E-Mail, Datenbank-/File-Server Beispiele P2P: BitTorrent, Blockchain/Bitcoin

OSI-Schichten: Der Unterschied besteht ausschliesslich auf der Anwendungsschicht – dort wird festgelegt, wer welche Rolle (Dienstanbieter/Dienstnutzer) einnimmt. Auf den darunterliegenden Schichten, insbesondere Transport- und Vermittlungsschicht, laufen beide Architekturen über das identische TCP/IP-Protokoll. Das ist die wesentliche Gemeinsamkeit.

Unterschied: Rollenverteilung (zentral vs. gleichberechtigt) auf der Anwendungsschicht · Gemeinsamkeit: identisches TCP/IP auf Transport-/Vermittlungsschicht

3Netzwerkmanagement: Manager, Agent, MIB14 Pkt.

a) (2 Pkt.) Man unterscheidet den Manager (Management-Prozess, läuft auf dem NMS) und den Agenten (Agent-Prozess, läuft auf der überwachten Netzkomponente).

Kurz: SMI legt die Bauregeln fest, die MIB ist die danach gebaute Objektdatenbank, und SNMP greift per OID auf die einzelnen MOs darin zu.

Lösungsweg

a) (18 Pkt.) Die Blockchain ist ein verteiltes, öffentliches, manipulationssicheres Transaktions-Logbuch (Distributed Ledger), das identisch auf vielen Rechnern (Nodes) eines P2P-Netzes vorliegt. Wesentliche Charakteristika:

- Transaktionen werden in Blöcken gebündelt - jeder Block ist über einen Hashwert mit dem vorigen verkettet (ein Merkle-Tree fasst die Transaktionen eines Blocks zusammen) - nachträgliche Änderungen sind erkennbar, da sie alle Folge-Hashes brechen würden - neue Blöcke entstehen per Konsensverfahren (Mining/Proof-of-Work); konkurrierende Miner lösen ein mathematisches Rätsel - bei Verzweigung (Fork) gilt: die längste Kette ist die gültige Kette; der kürzere Zweig wird zum Orphan-Block - Ursprung ist der Genesis-Block (erster Block der Kette) - dezentral: kein zentraler Verwalter/Intermediär nötig - transparent und praktisch unveränderbar - erweiterbar um Smart Contracts (selbstausführende If-Then-Verträge)

b) (6 Pkt.) Mindestens drei Industrien mit Verwendungszweck:

Finanzwesen → Kryptowährungen, Zahlungsabwicklung ohne Bank als Intermediär Logistik/Handel → lückenlose Herkunfts- und Lieferverfolgung von Waren Energieversorgung → dezentraler P2P-Stromhandel und automatisierte Abrechnung Medizin/Pharma → fälschungssichere, nachvollziehbare Patienten-/Chargendaten
a) verteiltes, verkettetes, konsensbasiertes Logbuch ohne zentrale Instanz · b) z. B. Finanzwesen, Logistik, Energie, Medizin
6Brute-Force und Social Engineering7 Pkt.
  1. Was versteht man unter einer Brute-Force-Attacke?
  2. Was versteht man unter Social Engineering und wieso ist es wichtig, dass bei allen Mitarbeitern eines Unternehmens immer wieder trainiert wird, hier sensibel und vorsichtig zu sein?
Lösungsweg

a) (3 Pkt.) Bei einer Brute-Force-Attacke probiert eine Software in schneller Abfolge systematisch alle möglichen Zeichenkombinationen durch, bis das richtige Passwort bzw. der richtige Schlüssel gefunden ist. Gegenmittel: lange, komplexe Passwörter/Schlüssel sowie Sperren nach mehreren Fehlversuchen.

b) (4 Pkt.) Social Engineering ist die gezielte psychologische Manipulation von Menschen – über Vertrauen, Hilfsbereitschaft, Autorität oder Druck –, um an Informationen oder Zugänge zu gelangen (z. B. Phishing, „Chef-Trick“). Regelmässiges Training ist wichtig, weil der Mensch das schwächste Glied der Sicherheitskette ist: Selbst die beste technische Absicherung wird wirkungslos, wenn Mitarbeitende getäuscht werden und Zugänge oder Daten freiwillig preisgeben.

a) systematisches Durchprobieren aller Kombinationen · b) Manipulation der Schwachstelle Mensch – Training als wirksamster Schutz
7Man-in-the-Middle: IP- und ARP-Spoofing18 Pkt.

Für eine Man-in-the-Middle-Attacke bieten sich verschiedene Verfahren an. Ein mögliches Verfahren ist das IP- und ARP-Spoofing.

  1. Worin unterscheidet sich IP- von ARP-Spoofing?
  2. Erklären Sie den Ablauf eines ARP-Spoofing.
  3. Kann eine Firewall gegen einen solchen Angriff schützen?
  4. Welche Massnahme kann helfen?
Lösungsweg

a) (2 Pkt.) IP-Spoofing fälscht die IP-Absenderadresse eines Pakets. ARP-Spoofing fälscht dagegen die Zuordnung zwischen IP- und MAC-Adresse im ARP-Cache der Zielrechner.

b) (6 Pkt.) Ablauf eines ARP-Spoofing:

1. Der Angreifer sendet gefälschte (Gratuitous) ARP-Replies ins LAN. 2. Diese verknüpfen seine eigene MAC-Adresse mit der IP-Adresse des Gateways bzw. des Opfers. 3. Opfer und Gateway übernehmen die falsche Zuordnung ungeprüft in ihren ARP-Cache. 4. Der gesamte Datenverkehr zwischen beiden läuft nun über den Angreifer (Man-in-the-Middle) → er kann mitlesen und manipulieren.

c) (2 Pkt.) Nein, in der Regel nicht: ARP-Spoofing spielt sich innerhalb des LAN auf Schicht 2 (Sicherungsschicht) ab, während eine Firewall meist am Netzübergang sitzt und den lokalen LAN-Verkehr gar nicht sieht.

d) (8 Pkt.) Wirksame Massnahmen:

- statische ARP-Einträge für kritische Systeme (z. B. Gateway) - Dynamic ARP Inspection (DAI) auf managed Switches - Port Security an den Switch-Ports - Netzsegmentierung / VLANs - Ende-zu-Ende-Verschlüsselung (TLS, VPN) gegen das Mitlesen - ARP-Monitoring bzw. Intrusion-Detection-Systeme (IDS)
a) IP- vs. MAC-Zuordnung gefälscht · c) Firewall hilft nicht (Schicht 2, LAN-intern) · d) DAI, Port Security, VLANs, Verschlüsselung, Monitoring
8Public-Key-Kryptografie6 Pkt.

Welche Aussagen in Bezug auf Public-Key-Kryptografie treffen zu? Hinweis: Es können sowohl nur eine als auch mehrere Antworten richtig sein.

    • (1) Die Nachricht kann mit einem öffentlichen Schlüssel (Public Key) verschlüsselt und mit einem geheimen Schlüssel (Private Key) entschlüsselt werden.
    • (2) Die Nachrichten werden mit einem einzigen kryptografischen Schlüssel ver- und entschlüsselt.
    • (3) Der geheime Schlüssel (Private Key) wird für das Signieren der Nachrichten und der öffentliche Schlüssel für die Verifikation der Signaturen eingesetzt.
    • (4) Jeder Nutzer hat ein kryptografisches Schlüssel-Paar, das aus einem geheimen (Private Key) und einem öffentlichen Schlüssel (Public Key) besteht.
  2. Teilnehmer A und B wollen mittels asymmetrischer Verschlüsselung Nachrichten austauschen. Mit welchem Schlüssel muss Teilnehmer B die Nachricht an Teilnehmer A verschlüsseln?
Lösungsweg

a) (4 Pkt.) Zutreffend sind (1), (3) und (4): Public Key verschlüsselt/Private Key entschlüsselt (1); Private Key signiert/Public Key verifiziert (3); jeder Nutzer besitzt ein Schlüsselpaar (4). (2) ist falsch – ein einziger Schlüssel für Ver- und Entschlüsselung beschreibt die symmetrische, nicht die asymmetrische Verschlüsselung.

b) (2 Pkt.) Teilnehmer B verschlüsselt die Nachricht an A mit dem öffentlichen Schlüssel (Public Key) von A. Nur A kann sie anschliessend mit seinem eigenen privaten Schlüssel wieder entschlüsseln.

a) (1), (3), (4) korrekt – (2) beschreibt Symmetrie · b) Verschlüsselung mit dem Public Key des Empfängers A
