Kapitel 1

Kurzcharakteristik und Entwicklung von C

Zuletzt gelesen

Was C ausmacht – und die Standards, die man zeitlich einordnen können muss. Diese Heftreihe legt C99 zugrunde.

Charakteristika von C
  • General purpose language, problemorientierte Hochsprache der 3. Generation (3GL) mit breitem Anwendungsspektrum.
  • Zugriff auf Bits, Bytes und Adressen → maschinennahe Programmierung; Zwischenstellung zwischen Assembler und Hochsprache.
  • Vereint zwei eigentlich widersprüchliche Eigenschaften: gute Hardwareanpassung und hohe Portabilität.
  • Grundbaustein sind ausschließlich Funktionen – alles wird in Funktionen organisiert.
  • Präprozessor für Textersetzung, bedingte Kompilierung und Codegenerierung.
  • Feste Scopes für Variablen, Unterstützung von Rekursion.
  • Ein- und Ausgabe sowie Speicherverwaltung sind nicht Teil der Sprache, sondern der C-Standardbibliothek (Quasi-Normung).
  • Speicherallokation statisch (zur Kompilationszeit), automatisch (Stack) und dynamisch (zur Laufzeit).

Kehrseite: Umfangreiche Projekte werden schnell unübersichtlich und fehleranfällig, weshalb C für sicherheitskritische Anwendungsentwicklung heute weniger geeignet ist und zugunsten von Java, C# oder Python zurückgegangen ist. Stark bleibt es in der Systemprogrammierung – Betriebssystemkerne (96 % von UNIX), eingebettete Systeme, Mikrocontroller – und als Erweiterungsschnittstelle kommerzieller Software.

Wichtig

C ist keine echte Teilmenge von C++. Die meisten C-Programme lassen sich zwar mit einem C++-Compiler übersetzen, aber nicht uneingeschränkt. Heutige Compiler sind meist beides und müssen für den gewünschten Sprachstandard konfiguriert werden.

Bei Erfolg gibt der Compiler nichts aus. Und: Laut Standard muss jede Quelltextdatei mit einem Zeilenumbruch enden.

2.2.2 Die main-Funktion

Jedes C-Programm braucht eine Funktion main als Einstiegspunkt. Bestandteile: Rückgabetyp int · Bezeichner main · (ggf. leere) Parameterliste · Körper in geschweiften Klammern. C unterscheidet nicht zwischen Prozedur und Funktion. Seit C99 gibt main automatisch 0 zurück, wenn nichts anderes angegeben ist – 0 meldet dem Betriebssystem den fehlerfreien Ablauf.

2.3 Die drei Phasen

PhaseErgebnis
Präprozessorbereitet den Quelltext auf (z. B. fügt #include den Inhalt der Header-Datei ein) → das Ergebnis heißt Translation Unit
Compilerübersetzt jede Translation Unit in ein object file (nativer Maschinencode plus Zusatzinformationen für den Linker)
Linkerfügt Objektcode und die Funktionen der Standardbibliothek zum ausführbaren Programm zusammen

Alle Präprozessor-Anweisungen beginnen mit # und stehen jeweils in einer eigenen Zeile.

One-Pass-Compiler → Deklaration vs. Definition

Ein C-Compiler liest jede Datei genau einmal, strikt von oben nach unten – kein Zurückspringen. Deshalb kann man nicht auf etwas zugreifen, das er noch nicht gesehen hat. Lösung:

Deklaration = teilt mit, dass etwas existiert und welche Form es hat (Typ). Definition = die eigentliche Beschreibung. Es darf beliebig viele widerspruchsfreie Deklarationen, aber nur genau eine Definition geben. Eine vorgezogene Deklaration heißt Forward-Declaration.

3.3 Undefined Behavior – das C-Thema schlechthin

Ein Programm kann syntaktisch und auf den ersten Blick semantisch korrekt sein und trotzdem undefiniertes Verhalten enthalten – etwa durch einen reservierten Bezeichner, Division durch 0, Lesen einer uninitialisierten Variable oder einen Array-Zugriff außerhalb der Grenzen.

Enthält ein Programm Undefined Behavior, ist es in seiner Gänze bedeutungslos – der Compiler gibt keinerlei Garantien mehr. Im besten Fall stürzt es ab, im schlimmsten fällt der Fehler erst nach vielen Betriebsstunden auf.

Warum gibt es das? Weil der Compiler bestimmte Bedingungen voraussetzen darf und dadurch wesentlich besser optimieren kann. Müsste er sie (zur Laufzeit) prüfen, wäre der Code ineffizienter – das widerspräche einem Grundgedanken von C.

Warnzeichen: Das Programm läuft ohne Optimierung korrekt, mit Optimierung fehlerhaft (oder umgekehrt) – ein sehr starkes Indiz für Undefined Behavior.

3.5 Datentypen

Die Basisdatentypen von C99: vorzeichenbehaftete Ganzzahlen (signed char, short, int, long, long long), ihre unsigned-Pendants plus _Bool, Gleitkommatypen (float, double, long double), komplexe Typen sowie void.

Größen sind nicht festgelegt

Der Standard schreibt keine festen Größen vor – einzige Ausnahme: char hat immer die Größe 1 (es ist aber nicht festgelegt, wie vielen Bits das entspricht). Garantiert ist nur die Relation

signed char ≤ short int ≤ int ≤ long int ≤ long long int

Mindestgrößen: short ≥ 2 Byte, long ≥ 4 Byte, long long ≥ 8 Byte, int mindestens so lang wie short (üblich 32 Bit). Konkrete Grenzen stehen in <limits.h> (z. B. INT_MAX) bzw. <float.h>, Typen fester Länge wie int64_t in <stdint.h>.

  • char ist ein eigener Typ – ob er sich wie signed char oder unsigned char verhält, ist implementierungsabhängig. Er repräsentiert die kleinste adressierbare Einheit; alle Größen sind Vielfache davon.
  • void ist die leere Wertemenge: keine Variablen möglich; als Rückgabetyp „kein Wert“, als Parameterliste „keine Parameter“, als void* Zeiger auf unspezifizierten Typ.
  • _Bool gibt es seit C99 und kennt nur 0 und 1. Empfehlung des Hefts: stattdessen <stdbool.h> einbinden und bool, true, false verwenden – das erhöht die C++-Kompatibilität.
  • sizeof liefert die Größe als Vielfaches von char, Ergebnistyp size_t (aus <stddef.h>), Ausgabe mit %zu. Bei Typen sind Klammern Pflicht – schreiben Sie sie immer.
3.6 Arithmetischer Überlauf

Vorzeichenlos: modulare Arithmetik – das Ergebnis ist der Rest der Division durch 2ⁿ. Beispiel mit 8-Bit unsigned char: UCHAR_MAX = 255, 255 + 5 → (260) mod 256 = 4.
Gleitkomma: Die Variable nimmt den Wert inf an; prüfbar mit dem Makro isinf aus <math.h>.

3.7 Literale

  • Ganzzahlliterale bekommen den ersten passenden Typ aus int → long → long long; Suffixe: l/L, ll/LL, u/U.
  • Oktal durch führende 0 (033), hexadezimal durch 0x/0X (0xC0FFEEul).
  • Gleitkommaliterale sind standardmäßig double; f/F → float, l/L → long double; abgetrennte Zehnerpotenz: 1.23e30.
  • Zeichenliteral in einfachen Hochkommas 'A', Zeichenkettenliteral in doppelten "Abc" (Array vom Typ char).
  • Literale liegen im Programmcode und sind nicht änderbar – der Versuch ist Undefined Behavior.

3.8 Typumwandlungen

Verknüpft werden können nur Operanden gleichen Typs, daher wandelt C implizit um. Zuerst die Ganzzahlerweiterung (char, unsigned char, short, unsigned short → int bzw. unsigned int), dann entlang der Hierarchie:

int → unsigned int → long → unsigned long → float → double → long double

Ausgenommen sind die Zuweisung sowie && und || – dort kann der Wert verloren gehen.

double d = 42.0;
float f = (float)d;  // expliziter Cast: Absicht sichtbar machen

double value = 3.8;
double result = (int)value * 5.0;  // 3 → 3.0 → 15.0 (ohne Cast: 19.0)

Merksätze

Implizite Casts sind eine häufige Fehlerquelle – der Compiler hilft mit -Wconversion. Ein expliziter Cast macht den Code nicht ineffizienter, aber lesbarer; er kann jedoch (wie oben) das Ergebnis verändern. Jede Umwandlung kostet Rechenzeit – unnötige vermeidet man durch eine sinnvolle Wahl der Datentypen.

3.11 const

Markiert einen Wert als unveränderlich (immutable state); ein Änderungsversuch ist Undefined Behavior, aber der Compiler warnt. const int a = 1; und int const a = 1; sind äquivalent („west const“ / „east const“). Achtung: Ein const-Typ ist nicht kompatibel zu seinem Pendant ohne const – nachträgliches Markieren kann eine ganze Änderungskette auslösen. Konsequent durchgezogen heißt ein Programm const-correct.

Kapitel 4

Steuerstrukturen

Zuletzt gelesen

Alternativen und Zyklen – im Struktogramm-Sprachgebrauch. Das Rückgrat jedes Algorithmus.

Arithmetischer und logischer Wert

C kennt bis C99 keine echten Wahrheitswerte. Deshalb steht in der Syntax überall „Ausdruck“, wo andere Sprachen „Bedingung“ sagen. Es gilt: Wert ≠ 0 → true, Wert = 0 → false. variable = 4; hat den arithmetischen Wert 4 und logisch damit true.

Übersicht der Steuerstrukturen: Block · Zyklen (for, while, do…while) · Alternativen (if…else, switch) · kontrolliertes Abbrechen (break, continue) · goto. Überall darf statt einer Einzelanweisung ein vollständiger Block stehen.

4.1 Auswahlanweisungen

if (ausdruck) {
  anweisung1;
} else {
  anweisung2;
}

Die geschweiften Klammern sind bei einer einzelnen Anweisung nicht nötig – guter Stil ist, sie immer zu setzen: bessere Lesbarkeit, keine Fehler bei Programmänderungen, und die Zuordnung des else bleibt bei Verschachtelung eindeutig. C ist formatfrei, die Einrückung entscheidet also nichts.

if-else gegen Auswahloperator

if-else ist eine Anweisung – sie tut etwas. Der Auswahloperator ? : ist ein Ausdruck – er liefert einen Wert. Wo beides möglich ist, ist die Operator-Variante vorzuziehen:

int a = b > 5 ? 100 : b * 20;

switch (ausdruck) {
  case konstante1: anweisung(en); break;
  …
  default: anweisung(en); break;
}

  • Der Ausdruck darf keine Gleitkommazahl ergeben – nur Ganzzahlen oder ein einzelnes char.
  • Abgearbeitet wird ab der Eintrittsstelle bis zum Ende des Blocks oder bis zum nächsten break.
  • default greift, wenn keine Konstante passt; die Reihenfolge der Zweige ist beliebig.
  • Guter Stil: auch den letzten Zweig mit break abschließen – semantisch egal, aber sicher bei späteren Erweiterungen.
  • Eine Variable lässt sich in einem case nur deklarieren, wenn man dort mit { } einen eigenen Block öffnet. Seit C99 sind Deklarationen mitten im Code erlaubt – das hält den Scope klein, was guter Stil ist (C90 verlangte sie am Blockanfang).

4.2 Schleifen

Schleifetypischer Einsatz
for (ausdruck1; ausdruck2; ausdruck3)Anzahl der Wiederholungen ist vorher bekannt
while (ausdruck)Prüfung vor dem Durchlauf – evtl. null Durchläufe
do { … } while (ausdruck);Prüfung danach – mindestens ein Durchlauf

break verlässt die Schleife vollständig, continue bricht nur den aktuellen Durchlauf ab. Auch hier gilt: Klammern immer setzen, das erleichtert die Wartung.

Kapitel 5

Datenstrukturen: Arrays, Structs, Unions

Zuletzt gelesen

Gleichartige Daten bündeln (Array), logisch Zusammengehöriges bündeln (Struct), denselben Speicher unterschiedlich deuten (Union).

5.1 Arrays

Elemente gleichen Typs, linear und lückenlos hintereinander im Speicher. Der Bezeichner steht für die Anfangsadresse. Zugriff über den Subscript-Operator [], null-basiert.

int numbers[] = { 2, 3, 5, 7, 9 };  // Größe aus der Liste – bevorzugt
int numbers[3] = { 1 };           // ergibt {1, 0, 0}
double matrix[][3] = {{1,0,0},{0,1,0},{0,0,1}};  // innere Größe ist Pflicht

  • Lokale Arrays müssen vor der Benutzung initialisiert werden; globale und statische werden automatisch mit null initialisiert.
  • Vor C99 musste die Größe zur Kompilationszeit feststehen, seit C99 darf sie zur Laufzeit bestimmt werden.
  • int a[5], b; deklariert ein Array und eine gewöhnliche Variable – solche gemischten Deklarationen besser vermeiden.
  • Zwei Arrays lassen sich nicht mit == vergleichen (das vergleicht Adressen) – elementweise in einer Schleife, für Zeichenketten strcmp() aus <string.h>.
Das Standardmuster für die Elementzahl

size_t count = sizeof(fibonacci) / sizeof(fibonacci[0]);

Gesamtgröße geteilt durch Größe des ersten Elements (40/4 = 10). Der Compiler rechnet das bereits bei der Übersetzung aus. Vorteil gegenüber dem Literal 10: Ändert man die Arraygröße, bleiben alle Schleifen korrekt. Zählvariablen ebenfalls als size_t deklarieren – das vermeidet unnötige implizite Umwandlungen.

Probleme mit Arrays
  • Index außerhalb der Grenzen = Undefined Behavior; C prüft nichts.
  • Endpunkte kontrollieren: Wird wirklich das letzte Element erreicht – oder schon die Struktur dahinter?
  • Bei mehrdimensionalen Arrays die Indexreihenfolge prüfen: Aus array[i][j] wird schnell array[j][i]. Besser row und column statt i und j.

Zeichenketten sind char-Arrays und müssen null-terminiert sein. Bei Literalen hängt der Compiler '\0' automatisch an – bei der Größenangabe mitzählen:

char name[] = "Douglas Adams";  // ≡ char name[14] = {'D','o',…,'s','\0'};
name[0] = 80;  // ASCII-Code erlaubt → 'P'
name[3] = "Test";  // UNDEFINED BEHAVIOR – ein Element ist EIN Zeichen

scanf("%s", array) liest nur bis zum ersten Leerzeichen, Tabulator oder Zeilenende.

5.2 Structs

Fasst zusammen, was logisch zusammengehört, aber verschiedene Typen hat – die Alternative wären mehrere parallele Arrays mit synchron gehaltenen Indizes.

struct order {
  int customer_id;
  int order_number;
  double price;
};  // Semikolon nicht vergessen!

struct order maier;            // Variable anlegen
maier.price = 12.23;          // Zugriff mit dem Punkt-Operator

struct order m2 = { 4711, 1234567, 12.23 };
struct order m3 = { .customer_id = 4711, .price = 12.23 };  // benannt

Die Definition beschreibt nur das Schema; Speicher wird erst mit der Variablendeklaration reserviert. Structs dürfen beliebige Typen enthalten, auch verschachtelte Structs.

5.3 Unions

Der Unterschied in einem Satz

Ein Union wird wie ein Struct definiert und benutzt – nur liegen seine Elemente nicht nacheinander, sondern überlagert im Speicher. Es kann also immer nur einen der Werte gleichzeitig aufnehmen; die Größe richtet sich nach der größten Komponente.

union database_entry {
  int integer;
  double floating_point;
  char string[64];  // bestimmt die Größe
};

In C (anders als in C++) darf man eine Komponente auslesen, obwohl zuletzt in eine andere geschrieben wurde – das Bitmuster wird dann als der entsprechende Typ gedeutet. Das nennt man type-punning.

Lösungsweg
#include <stdio.h> int main() { int total; printf("Sekunden: "); scanf("%d", &total); // Adresse uebergeben! int hours = total / 3600; int minutes = (total % 3600) / 60; int seconds = total % 60; printf("%d s = %d h %d min %d s\n", total, hours, minutes, seconds); }
Probe mit 52 665: 52665/3600 = 14 h · (52665 mod 3600) = 2265 → 2265/60 = 37 min · 52665 mod 60 = 45 s → 14 h 37 min 45 s.
3.5Warum hängt scanf("%d ", &a)?scanf-Falle

Welches Verhalten ergibt scanf("%d ", &a); – mit dem Leerzeichen hinter dem %d?

Lösungsweg

Obwohl man eine Zahl eintippt, passiert nichts – man kann beliebig weiter Leerzeichen eingeben.

Das Leerzeichen in der Kontrollzeichenkette verlangt nach der Zahl Whitespace. Da nicht festgelegt ist, wie viel, wartet scanf weiter. Erst ein Nicht-Leerzeichen (etwa ein Punkt) beendet die Eingabe. Merksatz: nie unbedacht Leerzeichen in die Kontrollzeichenkette schreiben.
4.1 / 4.2Division mit Nullprüfungif-else

Zwei Gleitkommazahlen einlesen, die größere durch die kleinere dividieren, Ergebnis ausgeben. Eine drohende Division durch null muss erkannt werden.

Lösungsweg
double a, b; printf("Zwei Zahlen: "); scanf("%lf %lf", &a, &b); // %lf fuer double! double gross = a > b ? a : b; double klein = a > b ? b : a; if (klein == 0.0) { printf("Fehler: Division durch null.\n"); } else { printf("%.4f\n", gross / klein); }
Zwei Punkte: bei scanf unbedingt %lf für double (bei printf wäre %f richtig), und die Nullprüfung vor der Division – Division durch 0 ist Undefined Behavior.
4.3Fehlersuche in einer for-SchleifeFehlersuche

Das Programm soll y = x² + x + 10 für x = 1…10 berechnen und die Teilwerte sofort ausgeben:

#include <stdo.h>
int main() {
  double y; int x;
  for (x=1, x <= 10, x++) {
    y=x^2+x+10;
  }
  printf("%2d. Ergebnis: %5d\n", x, y);
}

Lösungsweg

Fünf Fehler – zwei syntaktische, drei logische:

#include <stdio.h> // 1. Tippfehler: stdo.h -> stdio.h int main() { double y; int x; for (x = 1; x <= 10; x++) { // 2. Semikolons statt Kommas y = x*x + x + 10; // 3. ^ ist bitweises XOR, nicht "hoch" printf("%2d. Ergebnis: %5.1f\n", x, y); // 4. printf gehoert IN die } // Schleife ("sofort ausgeben") } // 5. y ist double -> %f, nicht %d
Der interessanteste Fehler ist x^2: In C ist ^ das bitweise Exklusiv-Oder. x^2 liefert für x = 3 den Wert 1, nicht 9. Für Potenzen entweder x*x oder pow() aus <math.h>.
4.4Zahlen ohne 7 – in allen drei SchleifentypenSchleifen · continue

Geben Sie alle Zahlen von 1 bis 250 aus, die weder durch 7 teilbar sind noch die Ziffer 7 enthalten. Lösen Sie es mit jedem der drei Schleifentypen.

Lösungsweg

Drei Ausschlussbedingungen – die dritte ist der Trick:

number % 7 == 0 → 7 ist Teiler (kein Divisionsrest) number % 10 == 7 → Einerstelle ist 7 number % 100 / 10 == 7 → Zehnerstelle ist 7 (bei 1..250 reicht das)
for (int n = 1; n <= 250; n++) { if (n % 7 == 0 || n % 10 == 7 || n % 100 / 10 == 7) continue; printf("%d ", n); } int n = 1; // while while (n <= 250) { if (!(n % 7 == 0 || n % 10 == 7 || n % 100 / 10 == 7)) printf("%d ", n); n++; } n = 1; // do-while do { if (!(n % 7 == 0 || n % 10 == 7 || n % 100 / 10 == 7)) printf("%d ", n); n++; } while (n <= 250);
Bei while und do-while lässt sich continue nicht so bequem nutzen: Dort würde es das n++ überspringen und eine Endlosschleife erzeugen – deshalb die negierte Bedingung.
4.5FizzBuzzSchleifen

Zahlen 1 bis 100 ausgeben, durch 3 teilbare als „Fizz“, durch 5 teilbare als „Buzz“, durch beide teilbare als „FizzBuzz“.

Lösungsweg
for (int n = 1; n <= 100; n++) { if (n % 15 == 0) printf("FizzBuzz\n"); // ZUERST pruefen! else if (n % 3 == 0) printf("Fizz\n"); else if (n % 5 == 0) printf("Buzz\n"); else printf("%d\n", n); }
Der einzige Stolperstein ist die Reihenfolge: Steht die 15er-Prüfung nicht zuerst, wird 15 bereits von der 3er-Prüfung abgefangen und nie „FizzBuzz“ ausgegeben. n % 15 ist gleichwertig zu n % 3 == 0 && n % 5 == 0.
5.1Würfelsimulation mit einer Million WürfenArrays · rand

Simulieren Sie das Würfeln mit zwei Würfeln. Geben Sie aus, wie oft bei 1 000 000 Würfen jede Augensumme fiel und wie oft ein Pasch vorkam. Nutzen Sie zur Zählung ein Array.

Lösungsweg
#include <stdio.h> #include <stdlib.h> // rand, srand #include <time.h> // time int main() { int counts[13] = { 0 }; // Index 2..12 genutzt, 0/1 bleiben leer int pasch = 0; srand((unsigned)time(NULL)); for (int i = 0; i < 1000000; i++) { int d1 = rand() % 6 + 1; int d2 = rand() % 6 + 1; counts[d1 + d2]++; // Augensumme als Index – der Trick if (d1 == d2) pasch++; } for (int s = 2; s <= 12; s++) printf("%2d: %7d (%.2f %%)\n", s, counts[s], counts[s] / 10000.0); printf("Pasch: %d\n", pasch); }
Kernidee: die Augensumme selbst als Index verwenden – deshalb ein Array der Größe 13. Erwartungswerte zur Kontrolle: 7 kommt mit 6/36 ≈ 16,7 % am häufigsten, 2 und 12 mit je 1/36 ≈ 2,8 %; Pasch 6/36 ≈ 16,7 %, also rund 167 000 Mal. rand() % 6 + 1 liefert 1…6; srand nur einmal aufrufen.

A.6Mittelwert beliebig vieler Eingaben15 Pkt.

Beliebig viele nicht-negative Gleitkommazahlen einlesen. Eine negative Zahl beendet die Eingabe und wird verworfen. Danach das arithmetische Mittel ausgeben – ohne alle Werte zu speichern.

Lösungsweg

Der Kniff steht in der Aufgabenstellung: Für den Mittelwert braucht man nur Summe und Anzahl – kein Array.

double value, sum = 0.0; int count = 0; printf("Zahlen eingeben (negative Zahl beendet):\n"); while (1) { scanf("%lf", &value); if (value < 0.0) break; // verwerfen und abbrechen sum += value; count++; } if (count == 0) printf("Keine Werte eingegeben.\n"); else printf("Mittelwert: %.4f\n", sum / count);
Zwei Dinge, die gern vergessen werden: %lf beim Einlesen von double – und die Prüfung count == 0, sonst wird durch null dividiert (Undefined Behavior), falls sofort eine negative Zahl eingegeben wird.
