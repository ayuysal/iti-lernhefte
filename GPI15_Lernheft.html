Kapitel 1

Von C zu C++: Streams und Namensräume

Zuletzt gelesen

C++ ist eine echte Obermenge von C: gültiger C-Code übersetzt auch als C++. Kapitel 1 zeigt die Erweiterungen, die man sofort braucht – die stream-basierte Ein-/Ausgabe und die Namensräume.

Grundbegriffe der Objektorientierung

Klasse = nutzereigener Datentyp, Bauplan (belegt keinen Speicher). Objekt/Instanz = Vertreter einer Klasse (belegt Speicher). Datenkapselung = Zugriff auf die Daten nur über Methoden. Vererbung = abgeleitete Klassen übernehmen Eigenschaften der Elternklasse. Polymorphismus = dieselbe Botschaft löst bei verschiedenen Klassen unterschiedliche Reaktionen aus; führt zum Überladen von Methoden und Operatoren.

Schwachpunkte im Design von C++

  • Manuelle Speicherverwaltung – die Sprache prüft nicht, ob ein Speicherbereich noch benutzt wird.
  • Unvollständige Objektorientierung – private Member stehen mit in der Header-Datei, erzeugen also Abhängigkeiten zur Compile- und Laufzeit; Objektspeicher ist zur Laufzeit nicht gegen gegenseitige Änderung geschützt.
  • Kontextabhängige Bedeutung – durch Operator Overloading kann z. B. << Linksschieben oder Ausgabe bedeuten; nur der Gesamtkontext entscheidet. Das kostet Compiler viel Zeit und Speicher.

1.2 Ausgabe: der Stream cout

Ein Stream ist ein Objekt, über das Daten zum Bildschirm „fließen“ bzw. von der Tastatur ins Programm. Der Ausgabeoperator << lässt sich beliebig oft aneinanderhängen – Formatelemente wie bei printf entfallen.

#include <iostream>
int main () {
  std::cout << "Hallo viel Erfolg mit C++!" << std::endl;
}

Header-Dateien werden in C++ ohne Suffix .h angegeben – so sind sie von den weiterhin vorhandenen C-Headern unterscheidbar.

endl vs. \n vs. flush

endl fügt einen Zeilenumbruch ein und leert den Puffer. '\n' bricht nur um; wann der Puffer geleert wird, entscheidet dann das System. flush leert nur den Puffer, ohne Umbruch. Durch Kombination von '\n' und endl steuert man das Puffern gezielt (Performance gegen sofortige Sichtbarkeit).

Manipulatoren

Ein Manipulator wird immer zusammen mit << ausgegeben. Für einen Teil ist zusätzlich #include <iomanip> nötig.

setprecision(4) auf 12.3456 gibt 12.35 aus – es wird auf die letzte Stelle gerundet.

1.2.2 Eingabe: cin

Analog überträgt >> von der Tastatur in eine zuvor angelegte Variable. Mehrere Werte unterschiedlichen Typs lassen sich verketten:

std::cin >> iZahl >> fZahl >> dZahl >> zeich;

1.3 Kommentare

C-Stil /* … */ (nicht schachtelbar!) und C++-Stil // bis Zeilenende.

Klassische Falle

Ein Block, der selbst /* … */-Kommentare enthält, lässt sich nicht mit /* … */ auskommentieren: Der Kommentar endet schon am ersten inneren */, das zweite */ liest der Compiler als zwei Operatoren * und /. Lösung: intern nur // verwenden – oder den Block mit #if 0 … #endif ausblenden.

1.4 Namensräume

std::cout ist ein qualifizierter Ausdruck: Namensraum std + Scope-Operator :: + unqualifizierter Bezeichner cout. Namensräume trennen gleichnamige Bezeichner verschiedener Bereiche – xyz::cout könnte etwas völlig anderes sein als std::cout. Alle Standardbezeichner von C++ liegen in std (Ausnahmen: Makros, operator new, operator delete).

FormBedeutung
using qualifizierter_Name;macht einen Namen unqualifiziert verfügbar (using ::std::cout;)
using namespace Namensraum;macht alle Namen des Raums verfügbar (using namespace std;)
::nameBezeichner im globalen Namensraum

Der globale Namensraum existiert immer, hat keinen Namen und enthält alle anderen. ::std ist deshalb eindeutiger als std, denn theoretisch könnte es ein ::ab::std geben.

Merksatz

using namespace std; nicht unreflektiert einsetzen: Die Bezeichner liegen nicht ohne Grund in einem eigenen Namensraum. Wer alles global verfügbar macht, hebt genau den Kollisionsschutz auf, für den es Namensräume gibt.

1.4.3 Reihenfolge im Quelltext

Präprozessor-Zeilen beginnen mit # und müssen je auf einer eigenen Zeile stehen (Ausnahme von der sonst formatfreien Schreibweise); ein Kommentar am Zeilenende ist erlaubt. Konvention: erst #include, dann using, dann der Rest.

#include <iostream>  // ::std::cout
#include <ostream>   // <<

Streng genommen verlangt << den Header <ostream>; kein aktueller Compiler besteht darauf, weshalb er meist weggelassen wird. Eine vergessene include-Anweisung macht das Programm trotzdem fehlerhaft – es kann nach einer Änderung oder einem Compilerwechsel auffallen.

Kapitel 2

Datentypen, Variablen, Referenzen, Felder

Zuletzt gelesen

Die Datentypen von C plus die C++-Zugaben: Referenzen, der Scope-Operator, const statt #define und die Klasse string.

2.2 Bezeichner

  • Nur Buchstaben, Unterstrich _ und Ziffern; das erste Zeichen darf keine Ziffer sein.
  • Beliebig lang, aber nur eine begrenzte Zahl Zeichen ist signifikant (heute meist bis 256, compilerabhängig).
  • C++ ist case sensitive. Schlüsselwörter dürfen nicht als Namen dienen.
  • Auch die Operatornamen not, and, or, xor, compl, bitand, bitor, not_eq, and_eq, or_eq, xor_eq zählen wie Schlüsselwörter; final und override haben Sonderbedeutung.

2.4 Literalkonstanten

  • Ganzzahlen sind immer positiv – -1 ist der unäre Operator - angewandt auf die Konstante 1.
  • Dezimal: Ziffern 0–9, erstes Zeichen keine 0. Oktal: beginnt mit 0, Ziffern 0–7 (010 = 8, 0100 = 64). Hex: beginnt mit 0x/0X (0xff = 255).
  • Typ = kleinster passender Typ; erzwingbar mit Suffix u/U (unsigned), l/L (long).
  • Gleitkomma: nur dezimal, Muster 1.23E-45, standardmäßig double; Suffix f/F → float, l/L → long double. 1F ist unerlaubt, 1.F erlaubt.
  • Zeichen: '*' ist ein Integer-Typ mit dem Zeichencode als Wert (ASCII 42). Escape auch als Code: '\x2a' = '*'.
  • Zeichenketten: "…", Typ char[], abgeschlossen mit '\0' → das Feld ist ein Zeichen länger als der sichtbare Text. Aufeinanderfolgende Literale verschmelzen: "St" "ri" "ng" = "String".

2.5 Variablen

Deklaration Datentyp Name; – muss vor der Verwendung stehen (nicht mehr wie in C zwingend am Blockanfang). Mehrere gleichen Typs mit Komma. Lokale Variablen sind ohne Initialisierung unbestimmt.

InitialisierungForm
Zuweisung (aus C)int a = 0;
Konstruktor-Initialisierung (nur C++)int a (0);

Gültigkeitsbereiche: außerhalb einer Funktion deklariert → global; innerhalb eines Blocks → nur dort bekannt. Da jede Funktion selbst ein Block ist, genügt der Blockbegriff als Definition.

Scope-Operator :: bei Variablen

Verdeckt eine lokale Variable eine gleichnamige globale, kommt man in C gar nicht mehr an die globale heran. In C++ erreicht ::b die globale Variable:

int b = 2;  // global
int main() { int a=1, b=10;
  c = a + b;   // 11 (lokales b)
  d = a + ::b; // 3  (globales b)
}

2.5.5 Konstanten: const statt #define

Nachteile von #define PI 3.141592653:

  • Der Compiler sieht den symbolischen Namen nie – im Debugger verwirrend.
  • Kein Gültigkeitsbereich einschränkbar.
  • Der Präprozessor arbeitet rein textuell ohne Syntaxprüfung – ein gleichnamiges Objekt wird ersetzt und erzeugt Syntaxfehler.

const double radius = 10;  // Wert ist Pflicht bei der Definition
radius += 1.0;  // Fehler: nicht änderbar
const int xxx;    // Fehler: Initialisierung fehlt

Ob der Compiler Speicher anlegt oder den Wert einsetzt, schreibt der Standard nicht vor. Gegenstück zu const ist volatile – Objekte, die sich ohne Zutun des Programms ändern (z. B. Systemzeit). mutable erlaubt Änderungen in Sonderfällen.

2.5.6 Referenz

Eine Referenz ist ein Aliasname für eine bereits existierende Variable. Sie muss bei der Deklaration gebunden werden und kann danach nie wieder gelöst werden. Steht eine Referenz links von =, wird nicht die Referenz, sondern die referenzierte Variable geändert.

int a;
int& ref = a;  // ref ist ein anderer Name für a
a = 4;  // ref ist jetzt 4
ref = 2; // a ist jetzt 2

2.6 Typumwandlungen

  • Integral Promotion: Typen kleiner als int (char, short, enum, Bitfelder, bool) werden automatisch nach int gewandelt; bool → 0/1, umgekehrt 0 → false, alles andere → true.
  • Zuweisung an kleinere Ganzzahltypen erfolgt ohne Warnung – Bits gehen verloren. unsigned int u = -1; warnt noch, der Umweg über int i = -1; unsigned u = i; nicht mehr (Ergebnis meist 4 294 967 295).
  • Gleitkomma: float → double → long double ist unkritisch, umgekehrt drohen Überlauf und Genauigkeitsverlust. Gleitkomma → Ganzzahl schneidet die Nachkommastellen ab (mit Warnung).
  • Übliche arithmetische Umwandlung: Bei binären Operatoren wird der „kleinere“ Typ an den „größeren“ angeglichen, Ergebnistyp ist der größere.
  • 0 darf jedem Zeiger zugewiesen werden (NULL-Zeiger). Jeder Zeiger geht nach void*, aber nicht zurück. Felder zerfallen automatisch zu Zeigern auf das erste Element.

Explizit (Cast): C-Stil (typ)wert weiter erlaubt; C++ bietet static_cast, const_cast, reinterpret_cast (statisch, zur Übersetzungszeit) und dynamic_cast (zur Laufzeit, für verwandte Klassen).

double c = static_cast<double>(a) / b;  // erzwingt Gleitkommadivision

2.7 Felder (Arrays)

Datentyp Name[Anzahl] legt ein statisches Feld an – die Größe ist danach unveränderlich und muss zur Kompilationszeit auswertbar sein. Indizes laufen von 0 bis Anzahl−1.

Häufigste Fehlerquelle

Es findet keine Prüfung zur Laufzeit statt, ob der Index im gültigen Bereich liegt. Der Programmierer allein ist dafür verantwortlich.

Der Feldname allein ist ein konstanter Zeiger auf das nullte Element: *feld ≡ feld[0], *(feld+i) ≡ feld[i]. ++feld ist deshalb verboten.

int i[3] = {10, 15, 20};   // Deklaration + Initialisierung
int i[]  = {10, 15, 20};   // Größe aus der Liste
char c2d[2][3] = {{'a','b','c'}, {'x','y','z'}};

Werden weniger Werte angegeben als das Feld Elemente hat, werden die restlichen wie statische Variablen initialisiert (mit 0).

sizeof – Elementzahl bestimmen

sizeof liefert die Speichergröße in Byte, unabhängig vom Inhalt. Die Elementzahl ergibt sich durch Division:

int i[10];   sizeof(i) = 40  → sizeof(i)/sizeof(int) = 10
double a[20]; sizeof(a) = 160 → /sizeof(double) = 20
char z[] = "Hallo"; sizeof(z) = 6  (inkl. '\0')

Vorteil gegenüber einer festen Zahl: Ändert sich die Feldgröße, stimmen alle Stellen automatisch.

2.8 Zeichenketten: die Klasse string

Echte C++-Erweiterung; benötigt #include <string> und den Namensraum std. Kein Grunddatentyp, verhält sich aber weitgehend so.

string zk = "Text";   // oder: string zk ("Text");
zk = zk + " und weiter";
zk += " und weiter";

Anders als beim char-Feld muss man sich weder um '\0' noch um die Länge kümmern; Zuweisung und Verkettung funktionieren mit =, + und +=.

Kapitel 3

Operatoren und Steuerstrukturen

Zuletzt gelesen

Operatoren, Verzweigungen und Schleifen – das Handwerkszeug. Klausurrelevant sind vor allem die Feinheiten: L-Werte, Auswertungsreihenfolge, Kurzschlussauswertung und die klassischen Fallen bei if, switch und ++.

L-Wert (lvalue)

Ein Ausdruck, der ein Objekt mit einer Speicheradresse bezeichnet – alles, was links einer Zuweisung stehen kann. L-Werte: Variablen x, Konstanten PI, dereferenzierte Zeiger *p. Keine L-Werte: 2, 2+a, Funktionsergebnisse. Nur von L-Werten lässt sich mit & die Adresse bilden; &2 ist unmöglich. Ein nicht-const L-Wert heißt modifizierbarer L-Wert.

3.1 Operatoren

  • Ganzzahldivision: 5/4 ergibt 1, 1/2 ergibt 0. Gemischt wird zuerst konvertiert: 5.0/4 = 1.25.
  • Modulo % nur für ganze Zahlen. Bei negativen Operanden implementationsabhängig: 7%3 = 1, (-7)%3 meist −1.
  • Zuweisungen sind rechtsassoziativ: a+=b+=c ≡ a+=(b+=c), während a+b-c ≡ (a+b)-c.
  • Eine Zuweisung ist ein Ausdruck, kein Statement – ihr Wert ist der zugewiesene Wert. Erst das Semikolon macht daraus eine Anweisung. Solche Seiteneffekte nur sehr kontrolliert einsetzen.
Prä- und Postfix

Alleinstehend sind ++a;, a++; und a+=1; gleichwertig. In größeren Ausdrücken zählt die Stellung: Mit a = 3, b = 7 ergibt
c = a++ + ++b; → c = 3+8 = 11, danach a = 4, b = 8.

Vergleichs- und logische Operatoren

  • == und != vergleichen beliebige Objekte; < <= > >= nur Zahlen und Zeiger (bei Zeigern: Adressvergleich).
  • Falle: a < b < c bedeutet nicht a<b && b<c, sondern wegen Linksassoziativität (a<b) < c.
  • ==/!= haben niedrigere Priorität, deshalb ist if (a<b == c<d) die Kurzform von if ((a<b && c<d) || (a>=b && c>=d)).
Kurzschlussauswertung (short circuit)

Bei && und || wird die Auswertung abgebrochen, sobald das Ergebnis feststeht: false && b = false, true || b = true – b wird gar nicht ausgewertet. Nützlich: if (i<index && a[i]!=0) prüft erst die Grenze. Gefährlich, wenn im zweiten Operanden Seiteneffekte stehen: while (++a<b && ++c<d) erhöht c im letzten Durchlauf nicht mehr.

Beliebter Fehler: & statt &&. Die bitweisen Operatoren brechen nicht ab und werten in beliebiger Reihenfolge aus: 1&2 = 0, aber 1&&2 = 1.

Komma-Operator: Ausdrücke werden von links nach rechts ausgewertet, der Gesamtwert ist der des letzten. Typisch in Schleifen: for (i=0,p=start; i<index; ++i,++p).

Konstante Ausdrücke (Feldgrößen, case-Marken) müssen zur Kompilationszeit auswertbar sein – nur Literale und benannte Konstanten, keine Funktionsaufrufe.

3.2 Verzweigungen

if (Bedingung)
  Anweisung_1;
else
  Anweisung_2;

Dangling else

Ein else gehört immer zum nächstliegenden noch freien if – unabhängig von der Einrückung. Nur Blockklammern { } erzwingen die gewünschte Zuordnung. Zweite Klassikerfalle: if (a=0) weist zu statt zu vergleichen (==).

switch (Ausdruck) {
  case Konst_1: Anweisung_1; break;
  case Konst_2: Anweisung_2; break;
  default: Anweisung_n;
}

  • Ausdruck und alle case-Marken müssen ganzzahlig bzw. nach int konvertierbar und zur Kompilationszeit auswertbar sein.
  • Nach dem Treffer wird bis zum Ende des Blocks weitergearbeitet – weitere case-Marken werden ignoriert. Ohne break fällt die Ausführung durch (häufige Fehlerquelle).
  • Reihenfolge der Marken ist egal, default muss nicht am Ende stehen. Intern meist als Sprungtabelle realisiert – ab drei Fällen effizienter und übersichtlicher als if-Ketten.

Konditional-Operator (ternär, rechtsassoziativ):

a = Bedingung ? Ausdruck_1 : Ausdruck_2;

3.3 Schleifen

FormPrüfungMerkmal
while (Bed.) Anw;vorherabweisend – evtl. null Durchläufe
do Anw while (Bed.);nachhernichtabweisend – mindestens ein Durchlauf
for (Init; Ausdr; Inkr) Anw;vorherZählschleife, alle drei Teile optional

Die for-Schleife ist exakt äquivalent zu:

Init;
while (Ausdruck) { Anweisung; Inkrement; }

for(;;); ist eine Endlosschleife. Mit dem Komma-Operator lassen sich mehrere Laufvariablen führen: for (i=1,j=10; i<=10; ++i,--j). Wird die Laufvariable im Init-Teil deklariert, ist sie nur in Kopf und Rumpf bekannt. Nach der Schleife haben Laufvariablen den Wert, bei dem die Bedingung erstmals nicht erfüllt war.

break / continue / goto

break beendet die Schleife ganz, continue nur den aktuellen Durchlauf (bei for wird davor noch das Inkrement ausgeführt). Beide beziehen sich auf die kleinste umgebende Struktureinheit – break also auch auf einen switch-Block, nicht auf die Schleife darum. Aus mehreren verschachtelten Schleifen kommt man damit nur eine Ebene heraus; nur dafür ist goto Marke; eine vertretbare Ausnahme.

Kapitel 4

Funktionen und Referenzen

Zuletzt gelesen

Die prozeduralen Sprachelemente vollständig: Deklaration und Definition, die drei Übergabearten, Überladen, Default-Parameter, inline, Funktionszeiger, main und Rekursion.

Deklaration vs. Definition

Deklaration (Prototyp, Signatur) = Rückgabetyp, Name, Typen der Formalparameter – beliebig oft erlaubt. Definition = Deklaration plus Rumpf – genau einmal pro Programm. In C++ ist eine Funktionsdefinition ohne Parametertypen nicht erlaubt; parameterlose Funktionen brauchen trotzdem Klammern: typ name(); bzw. typ name(void);.

C++ verlangt – anders als C – eine Deklaration, bevor eine Funktion benutzt wird. Argumente müssen nicht typgleich, nur kompatibel sein; es gelten dieselben Umwandlungen wie bei einer Zuweisung, deshalb funktioniert sin(1) (intern sin(1.0)).

return Ausdruck; beendet die Funktion sofort. Mehrere return sind erlaubt, aber zu vermeiden. Bei void genügt return; oder gar nichts. Der Rückgabewert darf ignoriert werden. Parameter verhalten sich wie lokale Variablen – bei Rekursion existieren mehrere Instanzen gleichzeitig.

4.1.3 Die drei Übergabearten

ArtDeklarationWirkung
call by valuevoid f(int w);Funktion arbeitet mit einer Kopie; Original bleibt unverändert
call by pointervoid f(int *w);Adresse wird übergeben, Zugriff über *w; Aufruf mit &var
call by reference (nur C++)void f(int &w);Alias auf das Original; Aufruf sieht aus wie by value
Wichtig für die Klausur

Am Aufruf allein ist nicht erkennbar, ob by value oder by reference übergeben wird – nur die Signatur verrät es. Genau das war früher das Argument gegen by reference: Dass eine Funktion etwas zurückgibt, sieht man; was sie verändert, nicht.

Literale lassen sich nicht an nicht-konstante Referenzen binden: add(1,2,erg) mit void add(int&,int&,int&) ergibt „invalid initialization of non-const reference … from a temporary“. Abhilfe: konstante Referenz int const&. Deren eigentlicher Nutzen: Es wird keine Kopie angelegt – bei int/double unerheblich, bei Strukturen und Klassenobjekten der Normalfall.

4.1.4 Felder als Parameter

Felder werden immer „by reference“ übergeben – weil der Feldname für einen Zeiger auf das erste Element steht. Diese drei Formen verhalten sich in der Funktion gleich:

void func(int *ptr) { … }
void func(int ptr[]) { … }
void func(int * const ptr) { … }

Die Indexgrenze braucht nicht angegeben zu werden (es wird ohnehin nicht geprüft). Vorteil der Zeigersicht – man kann Teilfelder übergeben:

sum(feld, 10);   // summiert 1..10 → 55
sum(feld+5, 3);  // summiert 6,7,8 → 21

Bei mehrdimensionalen Feldern müssen alle hinteren Dimensionen angegeben werden: void sum(int p[][3][4]);

4.1.5 Überladen

Mehrere Funktionen gleichen Namens mit unterschiedlichen Signaturen; der Compiler wählt anhand der Argumente. Auswahlreihenfolge:

  1. exakte Übereinstimmung,
  2. Datentypangleichung/Standardumwandlung (char→int, int→char*),
  3. benutzerdefinierte Umwandlungen.

Intern wird der „Abstand“ berechnet, die Instanz mit dem kleinsten gewinnt. Fehler, wenn keine passt oder mehrere gleich nah sind.

Was nicht überlädt

void test(int); und void test(const int); sind dieselbe Funktion – const beschreibt Verhalten, nicht die Signatur. Ebenso identisch: void f(double *ptr); und void f(double ptr[32]);. Dagegen sind int und long verschiedene Typen, auch wenn sie gleich groß sind. Klassiker: bei f(int) und f(char*) ruft f(NULL) die int-Variante auf, weil NULL als 0 definiert ist – nötig wäre f((char*)0).

4.1.6 Default-Parameter und variable Parameterzahl

Standardwerte sind nur für die hinteren Parameter erlaubt (sonst wäre die Zuordnung nicht eindeutig) und dürfen nur in der ersten Deklaration stehen:

void func(bool info = false);  // Aufruf: func(); oder func(true);
istream& getline(signed char*, int, char = '\n');

Für variabel viele Parameter endet die Deklaration mit …; mindestens ein echter Parameter muss davorstehen, denn seine Adresse ist der Ausgangspunkt. Auswertung mit den Makros aus <cstdarg>: va_list anlegen, va_start, je Wert va_arg(ap, typ), am Ende va_end. Standardbeispiel ist int printf(const char*, …) – riskant, weil ein falscher Formatstring die Parameter fehlinterpretiert (vertauschte Argumente können sogar zum Absturz führen). Die Streams von C++ sind hier deutlich sicherer.

4.1.7 inline statt Makro

inline setzt den Code an der Aufrufstelle ein statt zu springen: Programm wird größer, aber schneller (keine Stack-Formalitäten) und über Funktionsgrenzen optimierbar. Bei Schleifen/switch ignoriert der Compiler den Wunsch. Nie parametrisierte Makros verwenden: #define min(x,y) ((x)<(y)?(x):(y)) wird bei min(i++, j++) textuell ersetzt – eine Variable wird zweimal erhöht. Bei inline-Funktionen kann das nicht passieren.

4.1.8 Zeiger auf Funktionen

Der Funktionsname allein ist ein Zeiger auf die Funktion. Deklaration – die Klammern um * sind Pflicht, weil () stärker bindet als *:

void (*funcptr)(int, int);  // Zeiger auf Funktion
void *funcptr(int, int);   // Funktion, die void* liefert!

Funktionszeiger verhalten sich wie normale Variablen – Felder davon ergeben ein einfaches Menü/Dispatch. Beim Aufruf über einen Zeiger stehen keine Default-Werte zur Verfügung: f(2,3) ist Fehler, volume(2,3) dagegen 6.0.

4.1.9 main

  • main darf nicht selbst aufgerufen werden; das Programm endet mit ihrem Ende.
  • Rückgabetyp int (empfohlen) oder void; der Wert geht als Fehlercode ans Betriebssystem, return 0; = fehlerfrei. Fehlt es, ergänzen die meisten Compiler es automatisch.
  • Abbruch aus anderen Funktionen: exit(int) gibt Speicher frei und schließt Dateien, abort(int) nicht (beide aus <cstdlib>).
  • Parameterlisten: (void), (int argc, char *argv[]) oder (int argc, char **argv). argc zählt inklusive Programmname, argv[0] ist der Programmname.
  • Kommandozeilenargumente sind immer Zeichenketten – Umwandlung mit atoi() / atof() aus <cstdlib>.

4.2 Rekursion

Eine rekursive Funktion ruft sich selbst auf – alle Funktionen außer main dürfen das. Fast jede Rekursion lässt sich auch iterativ lösen; generell ist Iteration vorzuziehen, es sei denn, die rekursive Lösung ist einfacher, klarer und kürzer.

int potenz(int zahl, int exp) {
  if (exp > 0) return zahl * potenz(zahl, --exp);
  return 1;
}

5.1 Klassen modellieren mit UML

UML (Unified Modeling Language, OMG, ISO/IEC 19505) stellt 14 Diagrammarten bereit; das Klassendiagramm modelliert die statische, zeitunabhängige Sicht. Eine Klasse ist ein Rechteck mit Abschnitten (compartments) für Name, Attribute und Operationen – letztere sind optional.

SichtbarkeitBedeutung
+public
−private
#protected

Statische Attribute und Methoden (Klassenattribute/-methoden) werden unterstrichen. Die Multiplizität gibt die Zahl beteiligter Objekte als min..max an:

AngabeBedeutung
0..1kein oder ein
1genau ein (wird meist nicht notiert)
1..4mindestens 1, höchstens 4

Die Assoziation ist die allgemeinste Beziehung: eine Linie zwischen den Klassen, versehen mit Beziehungsname und Multiplizitäten, optional mit Navigationspfeil.

5.2 struct und class

Der einzige Unterschied

struct und class sind in C++ weitgehend gleichbedeutend. Sie unterscheiden sich nur im Standard-Zugriffsschutz: bei struct ist alles public, bei class alles private.

Die Definition wird mit Semikolon abgeschlossen (dazwischen ließe sich noch eine Variable deklarieren). Zugriff auf Elemente mit . bzw. über Zeiger mit ->; ptr->alter ist die Kurzform von (*ptr).alter – die Klammern sind nötig, weil . stärker bindet als *.

Der Speicherbedarf ergibt sich aus den Datenelementen, kann aber größer als deren Summe sein: Der Compiler darf zur Ausrichtung auf Wortgrenzen auffüllen und muss die Reihenfolge der Deklaration nicht einhalten.

5.2.1 Memberfunktionen (Methoden)

Neu gegenüber C: Methoden haben privilegierten Zugriff auf die Datenelemente. Definiert werden sie üblicherweise außerhalb, mit dem Scope-Operator, weil gleichnamige Methoden in anderen Klassen existieren dürfen:

Datum Person::gebtag() const { … }

  • const hinter der Argumentliste = die Methode greift nur lesend zu. Auf ein const-Objekt lassen sich nur konstante Methoden anwenden.
  • Im Klassenkörper definierte Methoden sind automatisch inline, auch ohne Schlüsselwort.
  • this ist ein Zeiger auf das eigene Objekt – nützlich, um Namensgleichheit aufzulösen: this->name = name;

5.2.3 Zugriffsschutz

SchlüsselwortZugriff erlaubt aus
publicüberall
privatenur aus Methoden der Klasse sowie befreundeten Funktionen/Klassen
protectedMethoden der Klasse und abgeleiteter Klassen

Der Schutz gilt klassenweise, nicht objektweise: Eine Methode darf auch auf die privaten Member eines anderen übergebenen Objekts derselben Klasse zugreifen. Der Status wird mit schlüsselwort: eingeleitet und darf beliebig oft wechseln.

Faustregeln

Datenelemente immer private. Schnittstelle nach außen public. Interne Hilfsfunktionen private – oder protected, wenn abgeleitete Klassen sie brauchen. Für den Zugriff Getter und Setter vorsehen: Sie kapseln die Repräsentation (man kann später intern von einem name auf vorname/nachname umstellen, ohne dass sich die Benutzung ändert) und können Plausibilitätsprüfungen vornehmen. Für schnellen Zugriff genügt ein inline definierter Getter.

class Person {
public:
  Datum gebdat() const;
  string nachname() const;
  void set_name(string);
private:
  Datum gebdat;
  string my_vorname;
  string my_nachname;

A.1Quadratische Gleichung mit Referenzen30 Pkt.

Für x² + px + q: a) int solve(…) gibt die Anzahl der reellen Lösungen zurück und liefert die Lösungen mit; b) display(…) gibt sie formatiert aus; c) Hauptprogramm testet (4,3), (−6,9) und (2,2). Parameterübergabe mit Referenzen.

Lösungsweg

Die Anzahl der Lösungen steckt in der Diskriminante der p-q-Formel: x₁,₂ = −p/2 ± √((p/2)² − q)

int solve(double p, double q, double& x1, double& x2) { double d = (p/2)*(p/2) - q; if (d < 0) return 0; if (d == 0) { x1 = -p/2; return 1; } x1 = -p/2 + sqrt(d); x2 = -p/2 - sqrt(d); return 2; }

x1/x2 sind nicht-konstante Referenzen – genau der Fall „mehrere Rückgabewerte“ aus Abschnitt 4.1.3. p und q können als double const& übergeben werden.

void display(double p, double q) { double x1 = 0, x2 = 0; int n = solve(p, q, x1, x2); cout << "x^2 " << (p < 0 ? "- " : "+ ") << fabs(p) << " x " << (q < 0 ? "- " : "+ ") << fabs(q) << " = 0" << endl; if (n == 0) cout << "hat keine reelle Loesung." << endl; if (n == 1) cout << "hat eine reelle Loesung:\nx1 = " << x1 << endl; if (n == 2) cout << "hat zwei reelle Loesungen:\nx1 = " << x1 << "\nx2 = " << x2 << endl; }
Probe: (4,3) → d = 4−3 = 1 → x₁ = −1, x₂ = −3 ✓ · (−6,9) → d = 9−9 = 0 → x₁ = 3 ✓ · (2,2) → d = 1−2 = −1 → keine reelle Lösung ✓

A.3Klasse Bruch40 Pkt.

Lösungsweg
