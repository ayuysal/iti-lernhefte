Kapitel 1

Typumwandlungen und Operatorüberladung

Zuletzt gelesen

Die vier Cast-Operatoren im Detail – und das Konzept, das es nur in C++ gibt: eigene Typen mit den eingebauten Operatoren verknüpfen.

1.1 Die Cast-Operatoren

OperatorWofür
static_cast<T>(a)ersetzt die C-Castings; nur wenn A implizit nach T umwandelbar ist (oder T nach A), wenn T ein enum-Typ und a im Wertebereich liegt, oder bei Zeigern voneinander abgeleiteter Klassen
const_cast<T>(a)entfernt oder ergänzt ausschließlich const; die Typen dürfen sich sonst nicht unterscheiden
reinterpret_cast<T>(a)schaltet die Typprüfung komplett ab – jeder Zeiger in jeden anderen, Zeiger ↔ ganze Zahl. Nur const lässt sich so nicht ändern
dynamic_cast<T>(a)dynamisch, erst zur Laufzeit bestimmt, für verwandte Klassen
Zwei Details, die gern geprüft werden

Der Compiler muss beim enum-Cast nicht prüfen, ob der Wert im Bereich liegt. Und: Ein Cast liefert keinen L-Wert – deshalb kann man so nicht in Referenztypen umwandeln; dafür gibt es den Referenz-Cast const_cast<T&>(a). Die Kurzformen T(a) (funktional) und (T)a (C-Stil) sind erlaubt, die Schlüsselwortform ist aber lesbarer und eindeutiger.

1.2 Operatoren überladen

Der Funktionsname ist das Schlüsselwort operator plus Operatorsymbol. Die Überladung muss so viele Parameter definieren, wie der Operator Operanden hat – als Memberfunktion entfällt das linke Argument, weil das Objekt selbst der linke Operand ist.

class Bruch {
  int zaehler, nenner;
public:
  int getZaehler() const { return zaehler; }
  Bruch operator*(Bruch);
};

Bruch Bruch::operator*(Bruch faktor) {
  Bruch tmp;
  tmp.zaehler = zaehler * faktor.getZaehler();
  tmp.nenner  = nenner  * faktor.getNenner();
  return tmp;
}
// Aufruf: c = a * b;

  • Argumenttyp möglichst const TYPE& – vermeidet unnötiges Kopieren.
  • Methoden, die nur lesen, als const deklarieren (auch Getter).
  • Steht die Überladung außerhalb der Klasse, hat sie nur Zugriff auf die public-Elemente.
Prä- und Postfix unterscheiden

Der Postfix-Operator bekommt einen künstlichen int-Parameter als Unterscheidungsmerkmal:

Point& operator++();    // Praefix: ++p – gibt *this zurück
Point  operator++(int); // Postfix: p++ – gibt den alten Wert zurück

1.2.2 Restriktionen

  • Nur bereits existierende Operatoren sind überladbar – keine neuen Symbole.
  • Es gelten dieselben Regeln wie beim Funktionsüberladen; passt nichts, meldet der Compiler „no match for operator“.
  • Eine Unterscheidung allein am Rückgabetyp ist nicht möglich.

Nicht überladbar sind:

()  ::  ?:  .  .*  sizeof  typeid()  throw
static_cast<>  dynamic_cast<>  const_cast<>  reinterpret_cast<>

Kapitel 2

Speicherverwaltung

Zuletzt gelesen

Stack oder Heap – und warum man die C-Funktionen und die C++-Operatoren niemals mischen darf.

StackHeap
Anforderungautomatisch bei der Deklarationexplizit durch das Programm
Freigabeautomatisch beim Verlassen des Blocksexplizit – sonst Speicherleck
Größe zur Laufzeit änderbarneinja
Schlüsselwortauto (wird nie geschrieben, ist Standard)new/delete bzw. malloc/free

Der Stack-Bereich einer Funktion enthält die lokalen Variablen, die mit den Argumenten initialisierten Parameter und die Rücksprungadresse. Bei return wird alles davon entfernt. Deshalb legt jeder rekursive Aufruf einen neuen Satz an.

Speicherleck und hängender Zeiger

Wird die Referenz auf dynamisch belegten Speicher überschrieben, lässt sich der Bereich weder freigeben noch nutzen – ein Speicherleck. Deshalb existieren Speicherfunktionen immer paarweise, und Bibliotheken, die Heap-Speicher herausgeben, müssen eine passende Freigabefunktion mitliefern.

2.3 C-Funktionen (aus <cstdlib>)

FunktionWirkung
malloc(s)s Byte reservieren, Rückgabe void*; Inhalt undefiniert
calloc(n,s)Speicher für n Objekte der Größe s, mit Nullen initialisiert
realloc(p,s)Größe ändern; realloc(NULL,s) ≡ malloc, realloc(p,0) ≡ free
free(p)freigeben; free(NULL) ist erlaubt und tut nichts

Rückgabetyp ist void*, weil der Speicher jeden Datentyp aufnehmen kann und void* zu allen kompatibel ist. Rückgabewert immer prüfen – bei zu wenig Speicher kommt NULL zurück. Diese Funktionen kümmern sich nicht um den Inhalt und sollten daher nur mit einfachen Datentypen verwendet werden.

if ((str = (char*) malloc(35 * sizeof(char))) == NULL) { … }

Mit sizeof statt einer festen Zahl bleibt der Code portabel – ein char ist nicht überall ein Byte.

2.4 C++-Operatoren

AusdruckWirkung
new T(…)Speicher für ein Objekt + Konstruktoraufruf (ohne Liste: Default-Konstruktor)
delete pDestruktor aufrufen, dann Speicher freigeben
new T[n]n Objekte, für jedes den Default-Konstruktor – Parameter sind hier nicht möglich
delete[] pDestruktor für alle Feldelemente, dann freigeben
Die wichtigste Regel des Kapitels

Die Verwaltungsarten niemals mischen. Auch new/delete und new[]/delete[] sind trotz des ähnlichen Namens nicht garantiert kompatibel. Im günstigsten Fall gibt es ein Speicherleck, im schlimmsten ist das Programmverhalten unvorhersehbar.

Kapitel 3

Ausnahmebehandlung

Zuletzt gelesen

Fehlerbehandlung, die vom eigentlichen Anwendungscode getrennt bleibt.

Error gegen Exception

Error (Fehler) = tritt wahrscheinlich auf – Programmierfehler, falsche Benutzereingaben. Dagegen hilft normale Prüfung mit if-else.
Exception (Ausnahme) = tritt höchstwahrscheinlich nicht auf – die gespeicherte Datei ist plötzlich unlesbar, der Speicher reicht nicht. Dafür gibt es die strukturierte Ausnahmebehandlung.

Der Vorteil gegenüber der alten Methode (nach jedem Funktionsaufruf den Rückgabewert prüfen): Die auslösende Funktion wirft eine Ausnahme, die alle Informationen zur Problemerkennung mit sich trägt. Der Behandlungscode steht getrennt vom Normalcode. Damit ist das Programm robuster, die Fehlerklassen sind unabhängig entwickelbar, und der Programmierer behält die Kontrolle über die Reaktion.

3.2 try-catch

try {
  // zu testender Code
} catch (bad_alloc& ex) {
  cerr << ex.what() << endl;
  exit(1);
}

  • catch (...) fängt jede Ausnahme – man erfährt dann aber nicht, welche.
  • Beim Werfen wird automatisch ein Objekt eines bestimmten Typs erzeugt; bei fehlgeschlagener dynamischer Allokation z. B. bad_alloc. Über diesen Typ wird ausgewählt, welcher catch-Block greift.
  • Das Objekt als Referenz & entgegennehmen – dann arbeitet man mit dem Original statt mit einer Kopie. what() liefert eine (meist knappe) Beschreibung.
  • Fehlermeldungen immer über cerr ausgeben, nicht über cout: cerr ist ungepuffert und lässt sich getrennt umleiten.
  • exit(n) aus <cstdlib> beendet das Programm; n ≠ 0 signalisiert dem Betriebssystem einen Fehler.

Kapitel 4

Klassen: Konstruktor, Destruktor, static, friend

Zuletzt gelesen

Der Kern des Hefts: Wie Objekte entstehen und vergehen, wie sie kopiert werden – und die zwei Ausnahmen von der Kapselung, static und friend.

Information Hiding

Eine Komponente soll nur über eine festgelegte Schnittstelle benutzbar sein, die von der Implementierung unabhängig ist – eine Änderung der Implementierung darf keine Änderung der Anwendung erzwingen. Ergänzt wird das durch Datenabstraktion: Zugriff nur über festgelegte Operationen.

Der Zugriffsschutz ist kein Schutz vor mutwilliger Änderung – umgehen lässt er sich immer. Er schützt vor versehentlicher Änderung und ist das Hilfsmittel für saubere abstrakte Typen.

4.2 Aufteilung auf Dateien

Klassendefinition in die Header-Datei, Implementierung in die .cpp. Header dürfen beliebig oft eingebunden werden, solange sie nur Deklarationen enthalten. Für Definitionen braucht es einen Include-Guard:

#ifndef __KURS6_H__
#define __KURS6_H__
class Kurs { … };
#endif

4.4 Konstruktor und Destruktor

KonstruktorDestruktor
Name= Klassenname= ~ + Klassenname

Anzahlbeliebig viele (überladen)genau einer, argumentlos

Fehlt ein eigener, stellt der Compiler Standardkonstruktor und Destruktor bereit. Der Standardkonstruktor ist der ohne Argumente.

Initialisierungsliste

Zwischen Argumentliste und Rumpf, eingeleitet mit : – mehrere Einträge mit Komma:

APerson::APerson(const string& a_name, const Datum& a_gebdat, int a_gender)
  : name(a_name), gebdat(a_gebdat), gender(a_gender) { }

Drei Punkte, die geprüft werden: (1) Der Compiler ignoriert die Reihenfolge in der Liste und initialisiert in der Reihenfolge der Deklaration im Klassenkörper. (2) Für const-Member, Referenzen und * const-Zeiger ist die Liste die einzige Möglichkeit zur Initialisierung. (3) Was im Rumpf steht, ist eine nachträgliche Zuweisung – aus Effizienzgründen also möglichst viel in die Liste.

Was wird automatisch initialisiert? Einfache Variablen: nur wenn static (dann mit 0), sonst undefiniert. Datenelemente, die selbst Klassen sind: immer über ihren Standardkonstruktor. Statische einfache Klassenvariablen werden einmal vor der ersten Instanz mit NULL initialisiert und danach von Konstruktoraufrufen ignoriert.

4.5 Kopieren und Zuweisen

Der Kopierkonstruktor nimmt eine Referenz auf ein Objekt desselben Typs entgegen: A(const A&);. Der compilergenerierte ruft die Kopierkonstruktoren aller Datenelemente in Deklarationsreihenfolge auf – für Klassen aus einfachen Elementen genügt das (bitweise Kopie).

Wann der generierte nicht reicht

Sobald der reguläre Konstruktor Ressourcen anfordert – dynamischen Speicher belegt oder eine Datei öffnet. Dasselbe gilt für den Zuweisungsoperator. Beide müssen dann selbst geschrieben werden, und der Standard verlangt, dass es nichtstatische Memberfunktionen der Klasse sind.

4.6 Statische Elemente

Existieren einmal pro Klasse, nicht pro Instanz, und leben über die ganze Programmlaufzeit – wie globale Variablen, aber (sofern private) nur in der Klasse sichtbar. Deklaration im Header, Definition in der .cpp:

class A { static int statischeVariable; static void statischeFunktion(); };
int A::statischeVariable = 5;  // Definition + Initialisierung

Statische Methoden

Sind an die Klasse gebunden, nicht an ein Objekt: aufrufbar ohne Instanz (qualifiziert mit dem Klassennamen), ohne this-Zeiger und ohne Zugriff auf nichtstatische Member. Typisches Beispiel: static bool ist_schaltjahr(int j) – das Ergebnis hängt nur vom Argument ab.

return (j%4 == 0) && (j%100 != 0 || j%400 == 0);

4.7 Befreundete Funktionen

Eine mit friend deklarierte Funktion darf auf private- und protected-Daten einer fremden Klasse zugreifen. Das widerspricht der Datenkapselung und schwächt sie ab – also nur mit Bedacht einsetzen.

Kapitel 5

Vererbung

Zuletzt gelesen

Neben der Kapselung das zweite Grundkonzept der OOP. Die zwei Zugriffstabellen in diesem Kapitel sind der am häufigsten geprüfte Stoff des ganzen Hefts.

Zwei Zwecke der Vererbung

Abstraktion – Klassen werden in einer Hierarchie aus Generalisierungen und Spezialisierungen angeordnet. Wiederverwendung – eine Klasse ähnelt der, von der sie erbt, unterscheidet sich aber in Details. Eine konkrete Vererbung kann beides erfüllen.

5.3 Zugriffsrechte – die zwei Tabellen

Zuerst: Wer darf auf ein Element der Basisklasse überhaupt zugreifen?

Dann: Wie verändert der Zugriffsmodifizierer bei der Ableitung diese Rechte?

Merksatz

Was in der Basisklasse private ist, bleibt in jeder Ableitung unzugänglich – Zugriff nur über öffentliche Methoden der Basisklasse. Durch Ableiten kann man sich den Zugriff auf private Elemente also nicht erschleichen. Die private-Ableitung nutzt man, wenn eine neue Schnittstelle entstehen soll: Es wird nur die Implementierung vererbt.

Jede Instanz der abgeleiteten Klasse enthält ein anonymes Objekt vom Typ der Basisklasse. Dieses wird vor den zusätzlichen Komponenten durch impliziten Aufruf des Basisklassenkonstruktors erzeugt.

5.4 „Ist-ein“ – wann ist Vererbung richtig?

Die Hierarchie stimmt, wenn sich alle diese Fragen mit Ja beantworten lassen: Ist ein A ein B? Ist A eine Erweiterung von B? Ist A eine Subklasse/ein Untertyp von B? Sind alle Elemente der Menge A auch Elemente der Menge B?

Unterklasse = Spezialisierung, Basisklasse = Generalisierung; beides sind inverse Prozeduren der Datenmodellierung. Bei der totalen Erweiterung muss jede Entität der Basisklasse auch Entität einer Unterklasse sein – die Basisklasse ist dann eine abstrakte Klasse. In UML: abstrakte Klassen und ihre abstrakten Methoden kursiv oder mit Stereotyp <<abstract>>, befreundete Klassen mit <<friend>>. Rein virtuelle Methoden lassen sich so darstellen – nur virtuelle Methoden kann UML nicht abbilden.

5.5 Virtuelle Methoden

Methoden, von denen man erwartet, dass abgeleitete Klassen sie redefinieren. Nutzen: Über einen Basisklassenzeiger oder eine Basisklassenreferenz wird die Methode der spezialisierten Klasse aufgerufen, ohne dass diese an der Stelle bekannt sein muss.

Der Effekt in einem Satz

Mit virtual in der Basisklasse gibt das Beispiel „Klasse A · Klasse X · Klasse Y“ aus – ohne virtual dreimal „Klasse A“.

5.6 Abstrakte Klassen

Eine Methode wird rein virtuell durch = 0 hinter der Deklaration; damit ist die ganze Klasse abstrakt.

class A { public: virtual void fkt() = 0; };  // abstrakt
// A a; → error: cannot declare variable 'a' to be of abstract type 'A'

  • Können nur aus Deklarationen bestehen; von ihnen werden nie Objekte erstellt.
  • Dienen oft als Schnittstelle (in anderen Sprachen interface) und als Startpunkt einer Hierarchie.
  • Alle abgeleiteten Klassen müssen sämtliche rein virtuellen Funktionen überschreiben – sonst sind auch sie nicht instanziierbar.
  • Vorteil: Beim Einsatz der abgeleiteten Klasse kann man sich darauf verlassen, dass die Methode implementiert ist.

5.7 Mehrfachvererbung

class KlasseAB : public KlasseA, public KlasseB { … };

  • Mehrdeutigkeiten bei gleichnamigen Elementen werden mit dem Bereichsoperator aufgelöst: ab.KlasseA::tuwas(); – der Aufruf ab.tuwas(); ließe sich nicht übersetzen.
  • Dieselbe Klasse direkt zweimal als Basis anzugeben ist verboten. Indirekt geht es – dann sind alle Basiselemente doppelt vorhanden.
  • Lösung: virtuelle Basisklassen – class KlasseA : virtual public Basis { … };. Dann existieren die Basiselemente in KlasseAB nur noch einfach.
  • Die Notwendigkeit ist umstritten: Mehrfachvererbung erhöht die Komplexität, fast alle Probleme lassen sich ohne sie lösen.

5.8 Befreundete Klassen: Mit friend A; in Klasse B erhält die ganze Klasse A Zugriff auf deren private Elemente.

Ein- und Ausgabe, Dateien

Was hinter cout und cin steckt – und wie man Dateien öffnet, prüft, positioniert und binär liest.

streambuf verwaltet den Puffer. ios ist die Basisklasse und besitzt ein streambuf-Objekt. Davon abgeleitet istream und ostream; iostream erbt von beiden. ifstream, ofstream und fstream ergänzen die Datei-Anbindung. Weil die E/A nicht Teil der Sprachspezifikation, sondern Bibliothek ist, bleibt C++ plattformunabhängig.

Kapitel 7

Generische Programmierung (Templates)

Zuletzt gelesen

Mit Templates verlässt man die objektorientierte und betritt die generische Programmierung: Funktionen und Klassen, die für beliebige Datentypen funktionieren.

Funktionstemplate

Eine Schablone, die dem Compiler mitteilt, wie eine Funktion zu erzeugen ist. Beim ersten Aufruf erzeugt er daraus eine „echte“ Funktion und ersetzt den Platzhalter durch den tatsächlichen Typ – den er allein aus den Argumenten ableitet, denn hier findet keine Typumwandlung statt.

template <typename T>
T max(const T& a, const T& b) { return (a > b) ? a : b; }

max(3, 7);      // T = int, automatisch
max<double>(3, 7.5); // explizit angegeben

Sprachgebrauch: Eine Templatefunktion ist ein Exemplar eines Funktionstemplates.

Voraussetzungen an den eingesetzten Typ: Der verwendete Operator (hier >) muss anwendbar sein, und es muss ein Kopierkonstruktor existieren, weil bei „call by value“ kopiert wird. std::string erfüllt beides. Mit const (und Referenz) wird das Kopieren vermieden und zugesichert, dass die Objekte unverändert bleiben.

Warum nicht einfach ein Makro?

#define MAX(a,b) (((a)<(b)) ? (b) : (a)) sieht generisch aus, bietet aber keine Typsicherheit – Fehler sind kaum überprüfbar. Eine gewöhnliche Funktion wäre typsicher, müsste aber pro Typ neu geschrieben werden. Das Template löst beides.

Klassentemplates lassen den verwalteten Typ offen, statt ihn bei der Klassendefinition festzulegen – die Grundlage der gesamten Standardbibliothek.

Kapitel 8

Fortgeschrittene Datentypen (STL)

Zuletzt gelesen

Container, Iteratoren, Algorithmen – die drei Bausteine der Standard Template Library.

Die C++-Standardbibliothek enthält die STL (Container plus Algorithmen), die C-Standardbibliothek, Strings, Streams, Typinformationen zur Laufzeit, Hilfen für dynamischen Speicher sowie Klassen für komplexe Zahlen und numerische Vektoren. Sie heißt „Template Library“, weil sie durchgehend Klassentemplates einsetzt.

Die drei Bausteine

Container – datentypunabhängige Sammlungen: vector<T>, deque<T>, list<T>, set<T>, dazu Warteschlangen, Stapel und assoziative Felder (maps).
Iteratoren – „Zeiger“, mit denen ein Container durchlaufen wird; sie entkoppeln Algorithmen von Containern. Die meisten Container liefern welche über begin() und end(). Arten: random_access, bidirectional, reverse, forward.
Algorithmen – arbeiten auf durch Iteratoren begrenzten Bereichen: sort, partition, fill, copy, replace …

Algorithmen lassen sich in drei Kategorien einteilen:

  • nichtmodifizierend – ändern weder Werte noch Reihenfolge,
  • modifizierend – dürfen Werte ändern und umordnen,
  • mutierend – ändern nur die Reihenfolge, keine Werte.

Eine Funktion, die ein Containerelement entgegennimmt und einen Wahrheitswert liefert, heißt Prädikat. Damit gibt man z. B. sort eine eigene Sortierregel mit.

Portabilität

Setzt man herstellerspezifische Bibliotheken ein, entspricht der Code nicht mehr Standard-C++ und ist kaum noch portabel. Daher zuerst prüfen, ob die Standardbibliothek die Funktionalität schon bietet.

Übung

Übungsaufgaben mit Lösungswegen

Zuletzt gelesen

Die Programmieraufgaben aus allen acht Kapiteln. Die Lösungswege sind eigene Ansätze – zum Abgleich, nicht als offizieller Lösungsschlüssel.

1.1/1.2Bruch um alle Grundrechenarten und Kürzen erweiternOperatoren

Erweitern Sie die Bruch-Klasse aus Beispiel 1.1 um +, − und / sowie um eine Methode zum Kürzen nach jeder Rechenoperation.

Lösungsweg
Bruch Bruch::operator+(const Bruch& b) const { Bruch t; t.zaehler = zaehler * b.nenner + b.zaehler * nenner; // Hauptnenner t.nenner = nenner * b.nenner; t.kuerzen(); return t; } // operator- analog mit Minus, operator/ = Multiplikation mit dem Kehrwert: // t.zaehler = zaehler * b.nenner; t.nenner = nenner * b.zaehler; void Bruch::kuerzen() { if (nenner < 0) { zaehler = -zaehler; nenner = -nenner; } int a = abs(zaehler), b = abs(nenner), r; while (b != 0) { r = a % b; a = b; b = r; } // ggT nach Euklid if (a > 1) { zaehler /= a; nenner /= a; } }
Zwei Details, die Punkte bringen: Parameter als const Bruch& (keine Kopie), Methode selbst const (Operanden bleiben unverändert). Das Kürzen gehört ans Ende jeder Operation.

5.1Ist Rechteck von Quadrat abgeleitet – oder umgekehrt?Vererbung · Theorie

Julia will Rechteck von Quadrat ableiten, Desiree Quadrat von Rechteck. Erklären Sie, wie die Meinungen zustande kommen, und wägen Sie ab.

Lösungsweg

Julias Argument ist das der Erweiterung: Ein Quadrat hat eine Seitenlänge, ein Rechteck zwei – das Rechteck fügt also etwas hinzu. Das klingt nach Spezialisierung, ist aber die Sicht „mehr Attribute = abgeleitet“.

Desirees Argument ist der Ist-ein-Test aus Abschnitt 5.4: „Ist ein Quadrat ein Rechteck?“ → ja. „Ist ein Rechteck ein Quadrat?“ → nein. Mengenmäßig sind alle Quadrate Elemente der Menge der Rechtecke, also ist Quadrat die Spezialisierung.

Nach den Regeln des Studienhefts hat Desiree recht: class Quadrat : public Rechteck. Fairerweise gehört die bekannte Schwäche dazu: Erbt Quadrat den Setter setzeSeitenlaenge(a,b), kann man ein Quadrat in einen ungültigen Zustand bringen – ein Objekt gerät über die Basisklassenschnittstelle in einen Zustand, den seine eigene Klasse nicht zulässt. Sauberer ist deshalb oft eine gemeinsame abstrakte Basisklasse Form mit rein virtuellen Flaeche() und Umfang().

6.2Binärdatei füllen, ändern, ausgebenbinary · seekp

Neue Binärdatei mit 1…50 füllen, danach alle durch 5 teilbaren Zahlen durch 99 ersetzen, abschließend zur Kontrolle ausgeben. Zwischen allen Teilschritten wird die Datei geschlossen.

7.2Klassentemplate Array mit GrenzprüfungTemplates · operator[]

Klassentemplate für ein Array, das sich wie ein Feld ganzer Zahlen verhält. Überladen Sie [ ] und prüfen Sie die Feldgrenzen.

Lösungsweg
template <typename T> class Array { private: T* daten; int groesse; public: Array(int n) : groesse(n) { daten = new T[n]; } ~Array() { delete[] daten; } // Destruktor ist Pflicht! T& operator[](int i) { if (i < 0 || i >= groesse) { cerr << "Index " << i << " ausserhalb 0.." << groesse-1 << endl; exit(1); } return daten[i]; } int size() const { return groesse; } }; Array<int> a(10); a[3] = 42; // ok a[10] = 1; // Fehlermeldung statt stiller Speicherverletzung
Genau das, was ein rohes C++-Feld nicht kann (Kapitel 2 in GPI15: keine Indexprüfung zur Laufzeit). Der Rückgabetyp muss T& sein, sonst wäre a[3] = 42; unmöglich – es braucht einen L-Wert.
